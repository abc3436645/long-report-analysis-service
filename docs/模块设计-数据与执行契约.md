## 1. 已确认约束与设计落点

主干固定为通用报告引擎、场景配置包、Agent适配层；不是三套业务工具或由某个业务主场景统领其他场景。Skill指导需要判断的任务和工具操作，状态化工具保存权威数据和执行确定性规则。四层映射如下，不增加重复实现：

| 执行层 | 复用现有模块 | 对外职责 |
|---|---|---|
| 场景配置 | scenario及三个配置包 | 加载目录、事实选择、公式/算子、方法论、提示词、模板及质量 |
| 解析与事实 | retrieval、ingest、evidence、analysis | 来源取得/解析、候选与有效事实、Fact Ledger视图、确定性指标 |
| 章节状态机 | project、planning、composition、storage | Section DAG、脏标记、任务版本、章节独立资产与允许变更集合 |
| 拼装与交付 | validation、rendering及project发布 | 复用章节组装、数值与哈希检查、完整文件验收及原子发布 |

Agent适配层统一CLI/MCP等入口和结果呈现，不复制上述规则；HTTP/MCP来源提供者适配仍按共用检索契约处理。ingest_engine、workspace_state、report_assembler是职责名称，不要求在已有模块外再套三组重复服务。

| 已确认约束 | 必需的模块边界 |
|---|---|
| 一个项目对应一个场景/对象范围/报告期 | 项目身份与报告修订分开，跨期建立关联项目 |
| 正常流程自动执行，歧义/冲突才交回用户 | 明确记录待裁决事项及受影响范围，不靠聊天记忆等待 |
| 材料提取不等于事实确认 | 保存原文位置、候选事实、可用证据及映射依据 |
| 利润类型、预算身份、期间、集团口径需要明确 | 数值不能只用“指标名＋数字”表示 |
| 表达局部改稿，事实/方法变化联动 | 章节保留事实、指标和前置发现的依赖关系 |
| 每轮完整文件，部分章节可复用 | 候选修订记录整份报告的章节集合及资产，不能只记录修改片段 |
| 满足场景规则可自动正式交付 | 质量结果绑定准确候选内容，不以导出成功代替验收 |
| 配置组合已有能力，新算法通过测试后扩展 | 场景包、项目覆盖、算子实现及版本分别管理 |
| 外部检索不与具体场景绑定 | scenario声明启用与需求，planning生成任务，retrieval执行归档，adapters连接提供者，evidence核验 |
| 必查证据不足仍继续报告，说明或请求补件 | 取证尝试结束与证据充分性分开；planning可带缺口推进，composition披露影响，validation沿用必要证据门槛 |
| 按场景时效复用并按需刷新 | retrieval保留查询及时间，planning按主体/条件/范围变化、过期或用户刷新生成相关任务 |
| 授信额度/等级由外部能力产生，期限随等级确定 | 接收带来源的业务结果供核对，不在报告引擎重建额度或等级模型 |
| 搜索线索不能直接充当关键事实 | evidence核验原文或专业记录的主体/时点/上下文，composition保留待核实与影响，validation核对论断支持 |
| 授信项目按事项和评价时间划分 | project保存适用的事项引用、评价基准和材料覆盖，补件与新事项分开 |
| 风险报告可先行，外部结果后补 | planning不以外部评估结束作为所有写作的前置条件，结果补充按依赖更新，不启动外部模型 |
| 授信专题包含在建项目，存在时说明并考虑 | 场景声明业务对象及专题，复用来源/证据、算子、发现和依赖，不另建报告项目或专用服务 |
| 风险程度独立于授信等级，事项跨材料关联 | 风险程度/影响、证据充分性、核验状态分开，稳定事项身份保留关联及歧义，不用重复出现次数累计风险 |

### 2.1 关键口径维度

对数值至少能表达对象、期间起止、当月/累计、指标类型、实际/预算身份、预算版本、币种、单位及集团/单位/汇总范围。含税状态、专项、组织变更和其他业务范围按适用性补充，未知不能默认相同。

报告期与同比/预算比较期分别记录。利润总额与净利润是不同指标类型；年度预算与进度预算不是仅靠展示名称区分的同一条数据。集团报表和单位汇总也不是同一个数值来源的可互换标签。

不同币种不能只改展示单位后直接比较；需要转换时，转换依据和适用期间必须有来源。日期明确表达期间，避免只保存“本期”“去年”这类依赖对话的简称。

Q45确定授信项目按事项/申请、业务单位和评价时间划分，补件/修订保留同项目，新申请或新评价基准建立关联项目。评价基准日、材料覆盖期间、事项发生日及检索时间分开表达，基准日后信息记录其纳入方式；适用事项和时间结构由场景声明，不在通用生命周期中按场景名硬编码。

### 2.2 来源定位

XLSX/CSV保留工作表或数据区、行列/单元格等可复查位置；DOCX保留段落/表格定位；PDF保留页及块定位。扫描或复杂版面失败记录实际受影响范围，不生成不存在的原文锚点。

来源能够打开、引用ID存在，只证明可定位，不证明语义支持相应结论。关键发现还需要核对主体、期间、上下文及反向证据。

预算场景的项目单位清单先由用户要求与本轮主表确定。自动提取映射若排除原表主体，必须给出范围理由并留存；发现应纳入主体时应更正项目范围后重新执行。完整报告计划逐份登记当前材料用途，已接受证据的来源不得标为背景或排除。章节、逐户证据与独立专项在交付前再次核验，语义相关性与解释深度由独立审阅者对照原件确认。

### 2.3 候选与有效身份

候选事实经适用检查后才可被分析使用。检查失败、来源冲突或映射歧义时，应记录原因和裁决范围；撤回/被替代的来源保留历史，不能继续当作当前有效依据。

证据的业务有效身份与任务的运行状态分开。是否叫`usable`、`conflicted`等属于工程命名，不改变“不能因模型自信而自动解决冲突”的确认规则。

### 2.4 数据结果与正文绑定

正文关键数值、表格、图表引用同一指标结果。金额、百分比、单位和期间的展示按结果元数据处理；模型负责解释含义，不另写一套不可追溯的表图数值。

来源变化、指标变化和结论变化分别跟踪。按已确认Q27，即使正文相同，有效依据、口径或交付身份改变也形成报告变化；重复请求不重复生效，不以文字差异作为唯一版本依据。

### 2.5 已确认的数值与对象规则

Q23确定：先检查口径，差额按实际减基准计算；正基数按声明公式计算变化率/完成率。零或负基数默认返回差额与明确状态，特殊百分率由场景定义。指标有利方向与数值增减方向分开，成本费用不能按“越高越好”判断；使用未舍入值计算后再按展示规则输出。

Q24确定：单位使用稳定身份与明确组织关系，别名可映射，重名/更名歧义请求裁决。分类节点不重复计入单位汇总；用户指定/模板顺序优先，其次组织顺序，再采用稳定缺省顺序。覆盖范围、展示顺序和分析深度不互相替代。

### 2.6 章节内容、资产与文件哈希

为落实Q52，至少区分以下校验对象；字段名和规范化细节属于工程建议，不能只比较带数值占位符的原始模板字符串。

| 对象建议 | 校验内容 | 用途 |
|---|---|---|
| section_source_hash | 持久化章节源内容，包括稳定的引用标记 | 检查宿主是否改写章节源，不单独作为可见正文不变的证明 |
| section_body_hash | 解析到指定指标版本/展示规则后的规范化正文，包含实际数值和单位 | Q52无关正文保护；规范化规则版本固定，不因不同运行随意忽略空格/文字变化 |
| section_asset_manifest | 该章绑定的表格数据、图表及其他内容资产版本/哈希 | 防止正文未改、表图内容变化；保护集合外资产直接复用旧不可变版本，不重新生成后冒充未变 |
| rendered_file_hash | 最终MD/DOCX及适用PDF实际文件字节 | 验证文件完整性，不要求因目录、分页或容器变化而整份DOCX哈希保持不变 |

内容绑定使用准确的指标结果/资产版本，而不只用可被重新指向的逻辑ID。若新的值会改变原章节可见正文或表图，应将其纳入影响评估；在保护集合外解析出不同内容就拒绝发布，不能在渲染阶段静默替换。明确锁定保留旧内容与其原依据，并按已确认规则显著披露冲突。

验收反例：章节源仍为同一利润引用标记，但数值从1亿元变为8000万元，source_hash可能相同，body_hash必须暴露变化；只改第三章措辞，其他章正文及资产清单保持，DOCX页码允许变化。实现仍需为规范化、引用和表图各提供样例，本文未运行该校验。

## 3. 模块输入、输出与失败边界

| 模块 | 输入 | 输出 | 必须显式处理的失败/不确定性 |
|---|---|---|---|
| scenario | 场景包及固定版本、项目覆盖要求 | 校验后的章节/分析/质量/模板定义 | 引用缺失、循环依赖、不兼容版本、未知算子 |
| project | 对象/报告期/场景/操作、基础版本 | 项目、更新运行、候选修订、交付清单 | 项目范围不明、版本冲突、提交未完成 |
| retrieval | 标准任务、配置的提供者能力、输入版本 | 实际返回与归档引用、检索状态及覆盖/时效限制 | 调用失败、未命中、部分结果、资源内容未取得；均不等于业务无风险 |
| ingest | 已登记文件、检索返回内容、解析范围 | 来源片段、表格、处理覆盖及失败范围 | 不支持格式、损坏文件、扫描页、复杂表格或公式结果无法确认 |
| evidence | 来源片段、候选事实、明确裁决 | 可用证据范围、冲突、缺口和来源关系 | 同名对象歧义、期间/单位不明、来源冲突、局部替代范围不明 |
| analysis | 有效证据和已声明指标/算子 | 指标、比较结果、数据表、不可计算原因 | 基数为零/负数、缺失输入、口径不兼容、汇总范围/抵销未明确 |
| planning | 项目操作、场景检索需求、材料/证据变化、章节关系 | 检索等任务、影响清单及前置条件 | 缺口、锁定冲突、未分类新材料、过期输入 |
| composition | 任务要求、证据/指标、前置发现、旧章节 | 章节、发现、引用和未决事项 | 证据不足、关键数字未绑定、结论与数据不一致 |
| validation | 完整候选、场景质量规则、审阅结果 | 定位明确的问题、修复任务、交付资格 | 错算/坏引用/漏单位、未完成审阅、检查未执行或结果过期 |
| rendering | 完整章节集合、数据表/图表、模板 | MD/DOCX及适用PDF、呈现检查结果 | 丢图、截表、字体/目录问题、格式导出失败 |
| storage | 模块写入与文件资产 | 可恢复状态、版本索引、可读取资产 | 文件缺失、内容不匹配、写入中断和历史引用失效 |
| adapters | 北向宿主请求、南向HTTP/MCP提供者调用 | 统一服务调用、协议/结果映射、上下文、可访问文件 | 参数无效、认证/协议错误、来源失败、工作区或文件不可达 |

核心计算不因出错而自动替换成模型估算。歧义待裁决不等于系统崩溃；系统崩溃也不能被包装成材料缺口。

## 4. 场景、项目与部署配置

- 场景包：版本化分析规则、默认章节、指标定义、检索启用/任务需求、适用条件、质量与模板资源。
- 项目要求：当前对象范围、报告期、预算比较版本、明确的章节/写作调整和锁定要求，不静默改动共享场景包。
- 宿主接入：工具连接、执行能力和文件呈现方式，不包含另一份预算计算或证据裁决逻辑。
- 提供者接入：共用的能力、HTTP/MCP服务及认证引用、请求/结果映射、超时与重试；不把供应商密钥复制到场景包。与宿主入口分别配置，避免混淆两个MCP方向。

优先关系必须由可校验的字段规则表达。业务用户可以明确调整项目要求，但不能通过一句“忽略检查”解除计算正确、来源可定位、必需文件完整等基础约束。

场景四文件的最小字段schema已由[工程结构与场景配置设计](工程结构与场景配置设计.md)确定；三个场景的具体可覆盖路径清单、业务参数及升级命令仍需实施样例收敛。本文不引入任意脚本执行或动态代码加载作为配置能力。

### 4.1 有效配置及缺口分类（Q54—Q55）

场景包声明`overridable_fields`及每项类型/约束，具体路径由场景实例填写并包含已确认允许的项目操作；未声明字段不可由项目覆盖。合成时先校验完整请求，任何未知字段、类型错误或越界都返回具体位置，不静默忽略或部分生效。项目身份改变按既有边界建立关联项目，不通过覆盖场景/期间字段绕过。

有效配置建议保留场景/模板/资源版本、项目要求版本、覆盖清单及来源、最终值和内容指纹。应用服务在运行开始时固定该配置，planning、analysis、任务上下文和validation引用同一身份；后续覆盖不改变已封存运行。硬数值/引用/文件检查不可关闭，共享场景包不被项目修改写回。

| 原因建议 | 识别与处理 | 对报告的约束 |
|---|---|---|
| invalid_configuration | 结构/引用/参数类型错误、未知算子、循环依赖、越界覆盖；拒绝运行或改令请求，给出位置 | 不用待复核掩盖配置错误，不损坏已交付版；不将外部服务运行失败误归此类 |
| definition_missing | 配置结构允许明确的未配置值，但业务口径、公式或展示规则未填；记录参数及依赖计算/章节 | 对应计算/展示不可执行，不补默认公式/阈值；其他满足规则的部分继续，必要要求不足待复核 |
| source_missing | 定义已有但所需材料未取得；记录所缺来源、范围及影响 | 按Q11/Q42披露并继续适用部分，不当零；可提出补件 |
| identity_unresolved | 项目主体/事项/期间等创建必要条件不明 | 按Q1/Q3先明确，不能生成对象或期间不明的报告 |

这些原因与任务运行状态分开；字段名不是已实现错误码。定义缺口记录建议包括缺失参数、影响的指标/展示/章节、是否影响场景必要要求、可继续部分及需要补充的定义。它不是材料已提供但值为零，也不等于场景明确不适用。

## 5. 章节结果建议

本节六部分保留 Q18 的早期预算示例，ID 为历史工程建议，不是通用引擎或场景的默认目录。所选七部分预算稿、授信七部分和薪酬章节草案也仅供本轮规划参考。现按 [ADR 0011](adr/0011-per-run-source-and-report-plan.md) 由 Skill 根据用户需求与材料生成章节计划，经 CLI 校验后冻结；`outline.yaml` 只声明稳定分析要点。通用契约要求章节身份、输入/输出、引用、依赖、表图和限制可表达。

| 建议ID | 对应已确认部分 | 内容职责与依赖方向 |
|---|---|---|
| `summary` | 执行摘要 | 读取本轮整体/专题/单位分析及主要问题，最后形成 |
| `overall` | 整体经营与预算执行 | 总体比较与预算情况，使用明确集团/企业口径 |
| `performance` | 收入、利润及成本费用分析 | 核心指标变化、结构与有证据支持的原因 |
| `unit_analysis/<对象ID>` | 各单位经营分析 | 按范围逐一展开，保持单位身份与显示章号分离 |
| `issues_actions` | 主要问题、风险及建议 | 整合相关发现、去除重复、保留限制，不能凭空指定既定负责人或承诺日期 |
| `basis_evidence` | 口径、材料缺口与证据附录 | 汇总本轮依据、预算版本、口径和问题，不代替正文限制披露 |

章节至少提交正文、关键发现、证据/指标引用、表图引用及未决事项。Q25已确认每单位有核心比较表或缺口说明，图表按可比性、分析价值及场景要求生成，不凑固定页数/字数。用户模板优先，缺省采用统一简洁Word样式；表格可编辑、图表真实嵌入、来源可追溯。正文明确区分材料记载、计算结果、分析推断和行动建议。

## 6. 已确认的执行、发布与审阅规则

Q26确定每项目一个活动更新运行，固定本轮输入，独立任务可并行，结果统一提交；缺少子Agent能力可顺序执行。运行中到达的新材料先登记供下一轮使用，过期输入结果拒收。

Q27确定先完成整份候选及必需格式检查，再切换当前交付版本。正文、表图、有效依据、口径或交付身份变化才产生新版本；相同请求重试不重复生效。回退形成新修订并按所选依据重新验收，历史保留，不把旧内容冒充已覆盖最新材料。

预算排版补充契约见[ADR 0012](adr/0012-budget-report-layout-contract.md)。项目创建支持可选`report_metadata`，仅接收单行`analysis_subject`、`prepared_by`、`confidentiality`，未知键或无效内容拒绝，不任意覆盖日期、数据性质和版本。发布从冻结证据区分当月/累计期间，从归档来源识别明确数据性质，实际生成日期在生成时取得；`report_version`采用V1.0起的可读递增版本，与内部修订ID及`evidence_snapshot_id`分别记录。历史无可读版本时保留原ID并说明首次建立版本。保密要求、数据性质或统计期间未核实，以及模拟数据进入`pending_review`说明。

渲染在发布暂存目录生成统一真实样式、独立封面、目录链接与重复表头。目录采用可靠字段更新或最终PDF实测收敛方案；当前转换入口使用后者并记录`toc_mode=static-measured`及原因，不能称已更新动态目录。`verify_docx`检查封面与已核实元信息、样式字号/字体、目录标题/条目/层级/目标/实测页码、表格宽度/重复表头/记录绑定/金额对齐和图片边界；图片哈希及PDF实际绘制另行校验。可确定缺陷抛错，暂存清理后保留原当前修订。最终逐页视觉审阅及实际Office兼容性检查仍须独立记录，不由结构检查推定。

预算正文由共用`build_draft`统一添加章节及小节编号，保留已有章号、单位编号、附录名称和Heading 4，不依赖验收脚本补号。财务列宽先保证完整数值可读；纵向容不下时，连同表题和紧接的来源段落置于局部A4横向节，后续内容恢复纵向，连续宽表不插入空白纵向节。超过A4横向可读宽度时明确要求将源表按列拆成附录，不压缩数字或丢列。页面尺寸、页边距、正文行距、孤行控制和标题分页绑定同样进入发布门禁。

Q28确定关键结论由独立审阅任务按同轮依据核对，可使用同模型不同上下文。程序检查计算、来源和资产，模型审阅语义。可修复错误定位返工且次数有上限，证据不足披露并待复核；必需审阅未执行不得标正式。

工程推导：材料集合先固定，候选事实核对后再封存有效证据。封存前可纠正候选；如需修正已封存依据，应以新依据替代旧运行、使受影响结果失效，不就地改写快照或接受混用结果。这是满足Q26的工程处理建议，具体恢复接口仍待验证。

### 6.1 任务交接与故障处理建议

| 情境 | 必须保留的信息 | 处理结果 |
|---|---|---|
| 任务就绪 | 明确输入依据和已完成前置任务 | 宿主取得对应上下文，不自行猜测遗漏依赖 |
| 用户裁决阻断 | 问题、选项依据、受影响范围 | 该分支等待，其余独立任务继续 |
| 相同提交重试 | 原请求身份、输入版本、结果摘要 | 相同请求返回既有结果；同一身份不同内容明确拒绝 |
| 过期结果到达 | 提交引用的输入与当前输入 | 拒绝覆盖并返回应使用的任务/依据 |
| 临时执行失败 | 错误类别、尝试记录、可重试性 | 按程序规则有限重试，超限显式失败 |
| 关键结论无充分依据 | 缺失依据和影响 | 修正为有限判断/缺口披露，不能用编造修复 |
| 构建或呈现失败 | 已成功步骤、候选资产、失败位置 | 当前交付版不变，返回恢复位置，旧版适用性明确提示 |

具体状态名和序列化字段仍为工程选择；这些记录必须支持无聊天历史时继续工作，不能只留在模型上下文。

### 6.2 事实来源与验收

Q29确认：首期报告事实来源限于上传材料和标明来源/版本的场景参考资料。不自行联网补事实；明确任务需要外部信息时记录其来源和时间，模型记忆不作为证据。本约束面向业务报告事实，不禁止实施阶段查阅软件官方文档。

C01—C02明确授信场景接收单位材料及通过HTTP/MCP取得的专业信息；企业信息软件及搜索引擎是来源类别，具体服务/账户仍待接入。C04将外部检索确认为通用模块，预算经营及其他场景同样通过配置启用和声明需求，不能将接入代码绑定授信场景。普通导出报告仍可作为上传材料，不再以导出优先描述主方案。

检索任务要求在运行开始时固定，计划内实际结果及缺口在证据封存前归档；封存后刷新遵守已有快照和版本规则。统一来源及状态见[通用检索契约](外部服务接入与证据契约.md)。Q42确认检索不足不阻塞进程，说明限制或请求补件，不能伪造成功，也不因请求用户补件暂停其他工作；技术调用状态、证据充分性和正式版资格分别记录，沿用Q11/Q22。检索方式问题仅在有依据时说明，未定位原因保持未知。

Q43确认按场景时效复用项目内归档快照；主体/查询条件/时间范围变化、有效期届满或用户要求刷新时重查相关任务。单纯措辞改稿不自动重查全部，检索与数据时点可追溯，不预设统一天数或跨项目共享敏感结果。

Q44确认搜索命中/摘要为线索，关键事实核验可追溯原文或专业记录的主体/时点/上下文，专业软件结论核对适用范围；无法核实时继续报告并保留待核实与影响说明。Q46确认风险报告可先行，外部结果后补后核对并更新相关依赖，不自动发起或重跑外部模型/评级流程。Q47的策略采用场景声明的建议类别，保留依据、适用条件与待核实项，既有措施与建议分开，不在composition中执行业务动作。

Q30确认：使用人工可核对的合成/脱敏样例，三宿主使用同材料、场景版本和指令，完成首次生成、补件、纠错、改章，并覆盖缺预算、冲突、新增单位、锁定和恢复。验收事实、计算、覆盖、版本和完整文件，允许措辞不同；耗时和用量仅记录实测，不能将设计描述当成通过记录。

### 6.3 单次运行的来源封存与结果有效性

以下为Q26、Q27、Q42—Q44的工程处理建议，不新增一套业务审批或状态平台：

1. start_update固定基础修订、操作、已登记上传来源及场景/项目配置版本，并固定本轮取证要求。新材料仍按Q26登记给下一轮，不能重指向本轮文件身份。
2. 上传材料可先解析，取证主体和查询条件核对后实例化本轮检索任务；实例绑定运行及输入版本，不擅自扩展已固定范围。按Q43复用或取得外部结果，有限尝试后如实保留失败/覆盖缺口。
3. 结果写入不可变来源资产并验证完整性，再提交来源记录与运行关联；崩溃留下的未引用资产不算已取得可用证据。重复接收同一结果不制造重复有效来源。
4. 来源清单汇总已归档结果、上传来源、核验状态和缺口后，登记证据快照及其具体来源版本引用。快照登记成功后才向分析/写作任务开放，不能读取尚未登记或实时变化的最新提供者结果。
5. 任务提交检查运行、任务版本及输入指纹；验收结果绑定候选内容和资产清单。版本不匹配的结果拒收；封存后刷新及新材料进入后续更新，不就地改写依据。

任务执行状态、结果是否仍适用于当前输入、当前交付是否覆盖待处理更新分别表达。成功完成的历史任务可以有过期输入，不能因此伪改为执行失败；历史报告可读不等于覆盖新材料。工程字段可用输入指纹比较及失效原因表示，无需把所有情形塞进同一个状态枚举。项目状态同时显示当前已交付修订、活动运行及待处理更新，不改写历史身份。

Q53—Q55已确认，运行替代/取消按6.4、有效配置及缺口按4.1处理。普通新材料的下一轮规则保留，不擅自扩大为所有用户指令都只能排队。

### 6.4 替代、取消与发布的提交边界（Q53）

替代/取消作为类型化操作进入统一应用服务，携带项目/目标运行、请求身份与幂等信息；替代还带新要求和明确的输入集合。自然语言含义由宿主提取为候选操作，程序执行版本校验、路由、状态变化与重试，不依赖模型记忆认定旧任务已停止。

| 时点/情境 | 工程处理建议 | 必须保留或拒绝的内容 |
|---|---|---|
| 接受替代/取消 | 在项目提交边界登记操作并撤销目标未发布运行的提交/发布资格，停止新任务派发 | 旧运行、用户操作、原因和原交付指针；不能只等worker自行停下 |
| 在途任务尚未返回 | 安全点结束在途工作；不可立即中断的调用结果归入旧运行记录 | 返回结果不得提交为有效结果或发布，不改当前交付 |
| 替代运行启动 | 旧运行退出活动资格后，以新操作/配置及输入建立新运行，仍只有一个活动更新 | 新旧运行关系、基础版本、固定输入；跨项目身份变化走关联新项目 |
| 替代要求存在配置错误 | 已明确撤销旧要求时，旧资格保持撤销；新配置校验失败则不启动该无效更新，返回错误和恢复位置 | 不部分应用新覆盖，也不以新要求无效为由继续发布已撤销的旧候选 |
| 旧候选已构建/已验收 | 验收记录绑定旧运行，资格撤销后不可发布 | 不删除审计记录，不挪用为新运行的有效验收；复用结果须重新验证输入指纹 |
| 取消后重试/旧任务迟到 | 幂等返回已记录结果或明确拒绝过期提交 | 不恢复旧运行资格，不制造第二次取消或重复新运行 |
| 发布与改令竞争 | 发布事务同时核对base_revision、活动运行身份及资格；以服务端提交顺序裁决 | 撤销先完成则拒绝发布；发布先完成则保留已交付历史，新要求另行更新，不声称已撤回旧交付 |

运行终止身份可分别表达被替代与被取消，具体枚举后续固定；它们不同于技术失败。任务历史结果、依据有效性和运行发布资格分别存储，不伪改旧事实。安全停止不允许在收到取消后继续推进发布；旧调用清理不算第二个活动更新。

待实施竞态样例：构建后替代、验收后取消、撤销与发布同时到达、旧任务迟到、替代请求重复、旧版本已交付后才收到改令。每例都要核对当前指针、活动运行数量及结果归属，本文未执行这些测试。

## 7. 通用性约束

证据、发现、章节与版本不限定为财务数据结构。预算经营使用数值与说明材料，风险尽调可使用合同条款/事项，薪酬分析可使用群体统计；业务差异进入场景包和算子，不能在通用项目生命周期中加入“如果是预算就……”的分支。

Q48的授信默认章节落在场景outline及任务依赖；Q49的专题与在建项目落在场景的对象/分析要求，Q50分级落在带来源的政策规则，Q51的跨材料风险事项关联复用发现和证据依赖。业务对象可引用单位下的在建项目等材料对象，不能混同报告Project；无须建立独立的“在建项目报告引擎”。

在建项目的身份/建设状态、投入及后续资金、融资落实、进度变更和单位现金流/偿债影响属于拟议分析维度，具体字段/口径需场景样例验证。已知映射与确定性计算由程序执行，材料提取及风险判断由宿主完成；不能因材料缺失推断没有项目，也不自动扩大到全部拟建项目。项目或材料变化经planning按真实依赖更新相关发现、章节、策略及摘要。

事项跨材料匹配保留关联依据；模型可提取/提出候选关联，明确身份映射由程序执行，歧义保留待核对，不把关键词相同或数值相同当作必然同一事项。风险分级无规则/依据不足保持待判定，不以宿主自评分代替企业政策。

三个独立配置包的实例分别见[预算经营](scenarios/预算经营分析-场景规格.md)、[授信风险审查](scenarios/财务公司授信评审-场景规格.md)、[人力薪酬](scenarios/人力薪酬分析-场景规格.md)。授信引用外部额度/等级结果、期限随等级确定；薪酬按Q37群体分析并限制主报告个人展示。业务差异由配置、规则和注册算子表达，不按场景名路由到另一套引擎。

Fact Ledger复用来源片段、候选事实、有效证据及指标记录，不是第二个可写事实源。每个指标保留数值口径、输入引用和算子版本，正文与表图引用该结果；章节复用不通过模型重抄正文。模型提交只允许更新当前任务被授权的章节，发布前校验被保护正文哈希；哈希不一致、引用损坏或结果过期必须显式拒绝，不以提示词承诺保护成功。

Q52已确认：事实/口径/结论变化时，受影响的关联章节纳入允许变更集合，其余正文哈希不变。表达修改只包含目标章节；无关正文从旧资产直接复用，不交给模型重写。planned集合、实际变更集合及保护检查进入运行/发布记录；集合外提交、过期结果或被保护正文哈希变化明确拒绝。显式人工锁定仍按Q13处理，不能以“有关联”绕过锁定。
