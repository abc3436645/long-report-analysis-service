# 区分材料缺口与阻止完整交付的错误

用户在2026-10-21第2轮Q11确认：材料不足时仍交付结构完整的待复核报告，在相关章节披露缺口、影响和不能作出的判断，并提供补件清单；未满足必要证据要求不得标为正式版。我们选择把证据完备程度与交付有效性分开，以支持持续补件和每轮完整交付，而不要求等全部材料齐备才提供报告。

错算、丢章、引用损坏和必需文件导出失败仍须修复，不能用待复核身份绕过。没有上次成功版本且本轮无法满足交付有效性要求时，显式返回失败与恢复位置，不虚称已交付完整报告；正式版具体门槛继续由场景细化。

第3轮Q22进一步确认：满足场景必要证据、数据/内容/呈现检查及语义审阅且无阻断冲突时，可自动标记正式版，不统一增加人工签发。特定场景有人工确认要求时才启用该项；正式版标记不自动代表业务负责人已批准。

用户在Q55进一步接受：结构/引用错误、未知算子或依赖循环属于无效配置，拒绝运行；结构合法但未填业务口径/公式/展示规则时，不猜定义，仅停止对应计算/展示并披露缺口，其余明确部分继续完整交付，必要要求不足待复核。项目身份/期间等创建条件仍须明确，不能借缺口策略跳过。业务定义缺口与材料缺口分开，不用此策略绕过错算、坏引用、丢章和导出失败。
