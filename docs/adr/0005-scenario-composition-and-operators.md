# 场景配置组合已有能力，新算法通过算子扩展

用户在2026-10-21第3轮Q20确认：实施人员维护版本化场景包，业务用户通过自然语言调整项目要求并留痕；已有分析能力通过配置组合，新算法允许增加经过测试的算子。选择这一边界，而不承诺任意新场景绝对零代码，是为了保持配置可理解、计算可验证，并避免把场景配置发展为另一套通用编程语言。

场景包的版本化业务规则与单个项目的要求调整分开记录。项目要求变化不应静默改写所有项目使用的场景包；具体覆盖字段和升级契约继续细化。

用户在C05重新明确Q38：主架构为“通用报告引擎＋场景配置包＋Agent适配层”，三个场景（财务公司尽调、预算办经营分析、人力薪酬分析）分别由配置文件驱动，交付采用Skill＋状态化工具。旧Q38“主场景＋专题组合”的推荐不作为架构中心或强制跨场景组合要求；业务分析任务可在各配置包内部组织，但不把某个场景固化为引擎主流程。

零代码接入的可验收范围是：使用已有解析器、注册算子及配置表达的新场景只新增配置包，不改引擎流程或增加场景名称分支。新增通用解析能力或全新算法仍按Q20扩展并测试，未知能力明确拒绝，不能让模型暗中补算；配置不是任意可执行脚本。

用户在Q54接受：场景显式声明可覆盖字段及类型，覆盖已有允许的项目调整；项目覆盖合成固定有效配置，记录来源和版本，不写回共享场景包。未知或越界覆盖明确拒绝，不能关闭数值、引用及必需文件等硬检查。各执行模块读取同一配置，不各自推断优先级；具体字段清单和schema仍待工程化。
