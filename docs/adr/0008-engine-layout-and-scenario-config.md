# 单包引擎、顶层场景配置中心与四文件契约

用户在 2026-10-21 确认先定稿工程目录与通用场景配置设计。三份需求分析提供分层与目录思路；后续[统一架构](../通用长报告项目-统一架构与业务流程.md)和[模块契约](../模块设计-数据与执行契约.md)已裁决旧示例中的冲突。本 ADR 将该目录与配置边界固定为后续实现依据，详细字段、树和样例见[工程结构与场景配置设计](../工程结构与场景配置设计.md)。

采用一个 Python 发行包，业务代码位于 src/long_report/，CLI/MCP 为共用应用服务的薄适配。顶层 scenarios/ 是三个并列场景的配置中心，每包有 scenario.yaml、outline.yaml、analysis.yaml、quality.yaml 和实际引用的资源。指标只引用经过测试的注册算子；新增场景在已有能力内只增加配置，新增解析能力或算法才扩展通用代码。场景配置不执行任意 Python。通用 Skill 维护一个源文件，平台壳负责装载和启动。

报告状态按 projects/<project_id>/ 隔离，以结构化状态为唯一权威；旧全局 .report_workspace/、多份可写 JSON 和每宿主单独 SOP 不作为目标结构。场景版本和项目有效配置固定并留痕，项目覆盖受类型化白名单约束，不得关闭数值、引用与必需文件等硬检查。北向宿主 MCP 与南向来源接入分开配置。

本 ADR 是设计决定，不表示源码、配置包、CLI/MCP 或三宿主实测已经完成。后续实现按主架构第 12 节逐阶段验证。
