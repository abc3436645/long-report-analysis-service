# 来源映射与章节计划按每轮材料和需求生成

2026-10-27更新：财务公司尽调的固定一、二级标题与字体按[ADR 0014](0014-financial-due-diligence-fixed-report-contract.md)执行；下文“不预置目录”继续适用于预算和薪酬场景，实时取证与每轮需求原则仍适用于全部场景。

用户于 2026-10-23 明确：所有场景从当轮上传原材料实时抽取并计算事实，不在场景包中预生成证据；预算报告可按当次需求分析矿山、其他板块或不同专题。主控 Skill 路由场景、阅读用户需求和本轮材料后规划章节、单位范围及依赖；场景四文件仅保存不变的计算口径、格式字体、分析要点和质量要求。对话增加要点形成新的报告计划和受影响章节更新，旧版本保持不变。

因此 `analysis.source_profiles`、`outline.profiles`、默认七章及固定单位名从运行场景配置移除。工作簿行列映射作为本轮 `task auto-submit.mapping` 输入并校验原件行名、文件、工作表和来源定位；首次 `draft plan` 必须提交 `report_request` 与完整 `outline`，由核心检查引用、重复范围和 DAG。历史参考映射与目录只保存在测试夹具，不能作为其他材料的证据或默认结构。续版可在创建章节任务前提交新的计划；改变已开始撰写的计划需开启新运行。

预算稳定规则增加带来源的金额差额、可比时的变化率和计划完成率，非正基期或转亏不输出机械百分比。具有利润事实的单位正文必须具备本单位利润表、经营指标或缺口表、可比时的本单位图和注册计算指标。参考 DOCX 仍用于核对内容深度、图表专业性和版式，不能作为预填正文。旧版 `pending_review` 报告是历史工程记录，不能据此宣称新流程已经完成业务验收。

本决定更新 ADR 0009、0010 中固定目录和板块 profile 的实施方式，不改变四份参考报告作为验收样本的地位，也不改变一个 Skill、三个场景包、一个 Python 核心和 CLI 首期入口。
