# 财务尽调金额按表图万元、正文分级单位展示

## 1. 决策依据

2026-10-30用户要求将金额展示规则写入财务公司尽调场景配置：图表金额统一万元，文本按金额大小使用亿元或万元；随后明确达到一亿元即使用亿元。该要求细化既有数值与单位一致性约束，不改变C02/C03的外部额度、评级及期限职责。

## 2. 决策

尽调场景升级为0.3.1，在`scenario.yaml.presentation.amount_display`声明表格单位、图形单位、正文常规单位、大额单位、以元计的分界值及默认小数位。共用展示逻辑读取本轮有效配置，不按场景名称分支。

表格与图形金额统一万元，图内金额差额注释同步换算，百分比等非金额注释保持原单位。正文按未舍入金额的绝对值判断：达到100000000元使用亿元，否则使用万元，负数及零值适用同一规则。默认展示两位小数，正文及表格引用的精度参数作用于换算后数值；原始证据及计算记录不变，核验继续使用原精度。

表格金额列和表注同步标明万元；没有统一金额列单位的混合信息表，金额单元格附带万元。正文自动添加金额单位，并吸收引用后已有的元、万元、亿元后缀，避免重复单位。原始材料应拆出独立、已核实的数值和单位，不对长段原文中的数字作猜测式改写。元每吨等单价、比例、人数等量纲不适用金额换算，币种或单位不明时须核实。

封面额度选择单位采用本次正文规则，更新[ADR 0016](0016-financial-cover-bindings.md)的固定亿元展示决定；`cover.amount_unit`仅为未声明`amount_display`的旧配置提供原展示规则。标题、额度来源、缺口处理及呈报日期绑定不变；封面沿用省略小数末尾零的简短金额表达。

图表资产身份包含金额展示配置，避免复用旧单位资产。任务上下文同时提供金额展示配置及写作指引。旧项目与历史修订不自动升级；需要新规则时使用0.3.1配置新建项目并重新生成，不直接编辑历史冻结状态。

## 3. 验证边界

回归覆盖原精度边界、负数、零值、引用小数位、非金额单位保留、表头表注、图形与注释、封面及冻结证据不变。全量测试、CLI场景加载及执行结果记录在[本轮记录](../../.scratch/financial-due-diligence-amount-display/spec.md)。这些检查不等于真实材料的业务签认。
