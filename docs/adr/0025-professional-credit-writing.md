# ADR 0025：专业成文以论据充分性为标准

状态：已接受（2026-11-04，用户要求以指定双稿和专业机构样本改进尽调撰写要求）。

## 1. 问题与决定

历史修订稿虽减少作业说明，仍存在从余额减少推导现金回收、从履历推导能力，以及泛化优势和结论不回应授信事项的问题。技术来源有效与文字流畅均不能证明判断成立。

作为C09及ADR0024的实施细化，统一采用“主张—证据—计算或推理—反向证据—结论强度—授信影响”的成文方法。正向与负向判断同样举证，事实、公司解释、推断和建议分别归属；润色不得扩大结论或删除重大限定。规范见[专业成文与论据规范](../scenarios/财务公司授信评审-专业成文与论据规范.md)。

## 2. 最小实现

financial_due_diligence升级0.3.5，收敛analysis.writing_guidance.report_expression并补充quality.chapter_expression_criteria。复用每章expression审阅，在既有通用criteria后追加场景标准；build、review及validate共用review_requirements，不增加审阅类型、数据库或自动语义裁决。

新字段可省略，旧冻结配置维持原要求。字段存在时必须同时启用chapter_expression_review且为非空字符串列表，非法配置拒绝加载。历史项目与报告不自动重写。主Skill、业务规范和测试同步，具体公司数值只放示例底稿，不进入通用提示词。

## 3. 验收与限制

验证每章收到标准、旧配置兼容、非法或未启用的标准不能静默忽略；现有CLI生命周期检验实际build输出及审阅门禁。双稿对照检验润色是否越界，由独立审阅者评价具体案例与规则。测试通过只证明要求传递及校验正常，不能称为新完整报告或业务认可。
