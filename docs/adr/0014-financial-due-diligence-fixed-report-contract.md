# 财务公司尽调采用真实交付样本的固定标题与字体

用户于2026-10-27提供真实交付DOCX，并明确财务公司尽调的一、二级标题和字体固定，要求基于现有架构配置当前场景。该明确要求更新[ADR 0011](0011-per-run-source-and-report-plan.md)对所有场景不预置目录的约束，并按Q48允许企业模板调整结构的约定替换旧七章默认目录。预算和薪酬场景仍按每轮需求规划；不混用两种目录模式。

原件为[真实交付样本](../../results/financial_due_diligence/关于2026年江铜华北（天津）铜业有限公司10亿.docx)，SHA-256为`6265ae3ae707a0a4ab0b0871ca46f81d88926a63e8999e51f72e585c22e87c88`。样本仅为标题、字体和内容深度依据，其企业、金额、人员、评级、期限、制度和授信公式不预置为其他项目事实或通用算法。

`outline.yaml`采用`fixed: true`，配置九章的稳定ID、标题、展示顺序、证据/分析引用及DAG，各章`subheadings`保存有序二级标题。27个编号二级标题按原文保留；第三章另将资产负债表、利润表、现金流量表、财务比率及分析四个未编号同级内容标题作为二级标题，保留原文冒号；第四章没有二级标题。空格缩进不作为标题内容。（一）类三级内容最初不固定；用户后续明确的股权结构及股东简介见场景规格第10.2节。详见[场景规格第10节](../scenarios/财务公司授信评审-场景规格.md#10-真实交付样本固定结构与字体)。

每轮仍提交当轮`report_request`及`outline.sections`，共享校验器核对固定标题、顺序、重复规则与二级标题；章节提交必须保留二级标题并提供内容或缺口说明，标题使用空行分隔的独立Markdown块；事实及来源引用展开后再次检查，避免多行材料内容被误解为新增章节。固定结构不替代本轮取证、分析和独立审阅；适用的其他风险在相关固定小节内使用三级内容表达，不能因模板而漏查。

`scenario.yaml.presentation`将正文、标题和拉丁字符字体统一指定为样本主要显式设置的“仿宋”，`allow_font_fallback: false`使缺字体时明确失败。样本早期二级标题继承Arial西文字体、第四章16磅而其他章15磅、表格字号20—24半磅等差异仅记录，不把偶发差异推定为已确认标准；本次未配置字号或完整版式复刻。

沿用一个Skill、四文件、共享引擎及现有`0.2.0`包版本，配置差异以fingerprint记录。历史项目、冻结配置和已发布版本不自动迁移；旧指纹项目继续发布时会被现有配置指纹保护拒绝，须显式处理迁移或保留对应运行环境。旧七章参考夹具仅作历史工程材料，不能用于新固定目录。已有项目如需采用本配置须显式新建或另行迁移，不能声称本次已完成存量升级。

验证应包括配置加载、标题/章节拒绝用例、精确字体拒绝回退及授信合成四轮流程。无仿宋的测试主机可在临时场景副本使用已安装字体验证生命周期，并单独验证真实配置的缺字体失败；该结果不属于真实报告的仿宋版式或业务签认。

2026-10-27后续补充：用户明确第一章工商信息必须使用含9个指定字段的表格，表头及单元格为仿宋五号（10.5磅）。通过`outline.sections.company.required_tables`配置并约束每轮计划、内容和局部渲染；具体字段和验证边界见场景规格第10.1节。本条更新前述“未配置字号”的范围，其余字号不自动统一。
