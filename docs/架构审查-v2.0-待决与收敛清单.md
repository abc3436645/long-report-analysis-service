## 1. 审查结论

三个独立配置包、通用引擎、Agent适配层及Skill＋状态化工具的根架构已经一致，不需要重新选择。剩余缺口集中在配置、运行、资产和业务样例契约，不能把已有原则当作可运行schema或通过记录。

本轮对主框架、模块契约、三个场景、检索、术语和七份ADR进行交叉审查；原始需求文档仍为来源，不覆盖后续已确认决定。检查分成两条只读审查线，分别审视架构一致性和场景契约；下表是合并复核后的结果，不把每条审查建议自动升级为用户待决事项。

## 2. 已可依据既有决定修正或补强的部分

下列字段和步骤是现有决定的工程表达建议，不是新的业务默认值，也未创建产品代码。

| 编号 | 发现与具体反例 | 处理及文档落点 |
|---|---|---|
| A01 当前状态仍有旧描述 | 主框架第6.1节仍称授信专题/章节待确认；模块第5节把预算六部分称为默认章节，容易误用到三个场景 | 修正授信已确认状态；预算章节明确只是示例；头部补齐三个场景及检索关联链接。历史轮次保留并标明不是当前状态 |
| A02 来源冻结路径不够明确 | 首次流程图中上传解析和检索分支可能分别进入核验，未表达统一来源清单封存点 | 修正为固定输入/检索计划→取得结果或记录缺口→汇总来源→解析核验→封存证据；结果归档但未封存时不能被写作引用，见主框架7.1及模块6.3 |
| A03 正文哈希可能漏掉数值变化 | 内部正文保持`metric_id`标记不变，组装却取到新数值；模板文本哈希相同，但读者看到的金额已经变化 | 按Q52保护引用解析后的正文，并检查表图资产；与完整DOCX文件哈希分开。不得仅凭模板字符串未变断言正文未变，见模块2.6 |
| A04 影响传播仍缺可执行说明 | 新担保材料未被旧正文引用，但可能推翻“未发现担保” | planning对实际引用、证据选择范围、对象集合、未满足要求取并集，再沿依赖反向闭包；无可靠分类时重评相关主题/项目覆盖，逐项记录原因，见主框架8.1 |
| A05 模板更新被过度简化 | 改字体与改表格列口径都被称为“模板变化”，实际影响不同 | 纯样式触发渲染及呈现验收；改变章节/表格语义或引用绑定则按对应内容依赖处理。有效资产/依据变化按Q27判定新修订，见主框架8.2 |
| A06 调用成功与正式身份需判定矩阵 | 企业信息接口失败，但上传的可追溯专业记录已满足同一必要证据 | 调用仍失败，证据可充分；在其余门槛满足时仍可正式。反之调用成功但主体不符不能算满足，见检索5.5；这不是重问Q42 |
| A07 配置仅有字段清单 | 三场景共享schema已明确，但缺少算子输入类型、证据选择器、重复对象、依赖和质量条件的互相校验 | 补最小配置契约分组及校验职责，不制造任意脚本语言，见主框架6.4 |
| A08 四层不等于四套包/服务 | storage服务多个阶段，容易被误实现成仅属于章节层的私有数据库 | 四层是职责视图，现有模块同进程协作；应用服务统一提交，storage为共享基础能力，禁止按四层复制状态；沿用3.1而非另选架构 |

场景版本固定与显式升级已在Q14/Q20及主框架6.2、10节规定，不新增“是否自动升级”问题。文档中四个核心YAML与提示词/模板/fixtures资源目录也不互相矛盾，本轮仅把说明写清楚。

## 3. 已确认的三个策略问题

| 编号 | 审查时的缺口 | 原因 | 当前确认与落点 |
|---|---|---|---|
| B01 | 运行中收到新的改稿/替代/取消指令 | Q26规定新材料下一轮，原先未明确新指令对旧候选的效力 | Q53已确认：安全停止/替代旧未发布运行，保留交付版，新要求固定到新运行，旧结果拒收；先撤销提交/发布资格，详见模块6.4 |
| B02 | 场景配置与项目级要求的覆盖权限 | 项目调整需要明确字段权限及一致的有效配置 | Q54已确认：仅覆盖场景显式开放字段，固定有效配置及来源；未知/越界明确报错，不允许忽略硬检查，详见模块4.1 |
| B03 | 业务参数未配置时的行为 | schema合法不代表薪酬口径、人效公式、小样本规则齐备 | Q55已确认：非法配置拒绝运行，未配置业务定义仅停相应计算/展示，其他明确部分完整交付并披露；必要要求不足待复核，详见主框架6.5及模块4.1 |

用户明确答复“Q53-Q55:按照推荐实施”，三项已生效，不再作为待答问题。没有待裁决的根架构选择；字段名、状态枚举和真实企业参数并未因此一并确认。

## 4. 仍需配置实例或业务样例验证的内容

| 范围 | 最小未完成工件 | 能暴露问题的样例 |
|---|---|---|
| 统一配置与工具 | 一份版本化schema、三份实例、类型化操作/上下文/结果/发布字段、错误样例 | 同一加载器接受三场景；未知算子、循环依赖、越权项目覆盖明确失败 |
| 事实与数值 | 稳定主体/业务对象、事实口径、来源版本、转换和算子记录 | 同名不同项目不合并；预算调整只作用声明范围；金额读取/单位/舍入可人工核对 |
| 薪酬 | 组成、应发/实发及计提/支付、期间、群体映射、人数/全职当量、人效公式、展示规则的实例 | 奖金计提期与支付期不同；岗位变动；缺人效分母；小样本不能通过拆分/交叉展示泄露被隐藏明细 |
| 授信及在建项目 | 现行政策来源、外部结果字段及期限关系；项目身份/状态、计划/实际/资金落实等不同口径 | 同一项目多材料不重复计数；计划总投资不加到实际现金流；专业软件评分不替代授信等级 |
| 预算 | 单位/集团映射、预算生效范围、利润类型、合并/汇总与抵销样例 | 部分预算替代、集团数据与单位汇总不等、零/负基数和缺预算 |
| 检索 | 提供者实际能力、权限、返回字段、覆盖、时效及证据采用规则 | 失败/空结果/部分结果、同名主体、摘要无原文、过期及迟到结果分别验证 |
| 资产与宿主 | 模板、目录/图表样例、完整文件可达性与3×3场景/宿主矩阵 | 只改措辞其余正文及表图不漂移；导出失败不切换版本；换宿主可恢复同一状态 |

参数应装入场景包/项目及部署配置，不写死到通用引擎，也不由模型凭经验补齐。真实企业参数无法从当前空业务样例中推断；可先用明确标为合成的参数验证引擎行为，不能声称代表真实政策。

## 5. 收敛顺序与验收边界

Q53—Q55已回答并写入主框架和模块契约，下一步是将其落实为同一schema、状态/接口定义、三个最小配置实例及可人工核对的合成fixture，再进入真实脱敏样例。材料规模、OCR/版式及服务接入按实际输入选定路线，避免先扩展更多模块。

本轮文档修正不能证明影响算法、哈希保护、事务恢复或三宿主兼容已经有效。既有架构无需重建，但在最小配置、工具字段和fixture完成前，不应称为可直接实现且已全面验收的规格。
