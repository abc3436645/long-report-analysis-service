# 首期实施蓝图：主控 Skill、三场景与 Python CLI

状态：设计基线及实施进展｜Q59确认首期以合成服务验证通用南向 HTTP/MCP 契约，真实供应商联调另验；Q60记录 `0.1.0` 最初只是配置骨架。旧版 0.1.0 已完成三场景合成四轮、三宿主同 wheel 的脚本化 CLI 回归、南向合成 JSON 服务验证及预算 MOCK 参考数据的完整待复核报告；当前 0.2.0 的动态规划与图表分析仍需重新验收，证据见[首期工程验收](../.scratch/long-report-first-release/acceptance-2026-10-23.md)。宿主自主撰写、真实供应商联调和业务口径签认未完成。本文沿用已接受的[统一架构](通用长报告项目-统一架构与业务流程.md)、[模块契约](模块设计-数据与执行契约.md)及[工程结构设计](工程结构与场景配置设计.md)。

## 1. 目标与成功标准

首期交付一个可安装的 Python 包、一份主控 Skill、三个版本化场景包和一个 CLI。三个场景分别是预算经营分析、财务公司授信评审和人力薪酬分析。主控 Skill 规定分析流程，并根据本轮需求与原件制定章节及依赖；Python CLI 加载场景稳定配置、分析要点和计算口径，再接收本轮来源映射、章节计划、任务与结果。Python 核心引擎负责配置校验、持久状态、确定性计算、影响传播、验收及发布。Codex、Claude Code、DeepSeek Harness 使用同一场景版本、命令契约和项目工作区，不分别实现业务规则。

首期是工程验收版。成功需要由运行证据证明：三个场景各能从可人工核对的合成或脱敏材料生成完整 Markdown 与 DOCX，并完成首次生成、补件、更正和指定章节修改；预算场景验证预算版本与同口径比较；授信场景验证外部结果缺失及后补、风险事项和来源核验；薪酬场景验证群体口径、人效定义、小样本展示限制及个人明细不外露；中断后可恢复，失败不覆盖当前已交付版。三个宿主分别跑通同一 CLI 流程并能访问最终文件。措辞可以不同，事实、数值、章节覆盖、版本和交付身份必须满足同一场景规则。尚未取得真实企业政策和参数时，不宣称可正式业务投用。

Q60 所述 M0 是实施起点。当前同版本开发快照已具备项目、取证、计算、修订和 MD/DOCX 交付；M4 的脚本化 CLI 部分已有三宿主运行记录，开放式 Agent 写作与复核仍需另行实跑。版本号本身不代表业务验收通过。

## 2. 五个交付物的责任

| 交付物 | 首期责任 | 不承载的责任 |
|---|---|---|
| 主控 Skill | 规定首次生成、补件、更正、改章、审阅和交付的流程；指导宿主按CLI返回的任务与阻断原因推进，提交提取、分析、写作及独立审阅结果 | 保存权威状态、定义场景计算口径或放宽发布门槛 |
| 预算经营场景包 | 对象与期间、材料需求、稳定指标与比较规则、逐户分析要点、表图质量和样式资源 | 复制一套预算专用引擎 |
| 授信评审场景包 | 授信事项与评价基准、专业来源需求、稳定风险审查与策略要求、外部结果核对及质量门槛 | 重建授信额度模型、评级流程或替换外部结果 |
| 人力薪酬场景包 | 人员与群体范围、薪酬组成和期间口径、分组统计与人效定义、展示限制及质量要求 | 默认展示个人薪资，或在缺公式、缺小样本规则时自行补定 |
| Python 核心引擎 | 通过CLI暴露场景加载和领域操作；在核心中校验四文件配置、注册算子及章节DAG，执行项目与材料、证据、计算、任务、修订、文件生成及验收 | 在CLI参数解析器中复制场景业务逻辑，或依赖某个宿主SDK执行核心业务 |

每个场景包首期提供一套版本化内置 Word 模板。用户提供的 Word 可作为改稿或样式参考，首期不承诺自动导入任意 Word 并生成可用模板；场景允许的项目级模板调整仍按 Q54 校验和留痕。

主控 Skill 的单一维护源沿用 `.agents/skills/long-report/SKILL.md` 设计。宿主入口只负责发现 Skill、启动同一个 `report` CLI 并呈现产物。安装与路径可达性需要分别在三个宿主实测；不能因 Skill 文件可读取就判定集成完成。

## 3. 首期最小调用链

CLI 把[统一工具接口](通用长报告项目-统一架构与业务流程.md#10-统一工具接口与宿主交付)映射为命令；从调用者看由CLI加载场景，内部由共用核心加载器解析四文件并校验引用、算子和DAG，CLI本身只映射参数、结果和错误。字段及命令拼写在实现前以一个端到端样例固定，不在 Skill 中另造第二套协议。所有命令输出结构化结果或明确错误，并携带项目、运行、任务和基础版本身份。

1. `create_project` 接收明确的场景ID/版本，加载稳定分析要求与计算口径，再按本轮需求与材料识别对象并固定项目身份、对象、期间和允许的材料处理范围。
2. `add_materials` 登记原件与版本关系；`start_update` 固定本轮输入，创建解析、取证、计算、分析和写作任务。
3. 宿主按Skill流程循环调用 `list_tasks`、`get_context`、`submit_result`；模型负责当前原件候选提取、章节规划、判断、正文和语义审阅，程序负责映射/计划校验、任务就绪、重试、数值和状态判断。
4. `build_revision` 组装完整候选；`validate_revision` 检查计算、引用、章节、表图、文件及审阅状态；`publish_revision` 原子切换当前版并返回完整文件。
5. 宿主中断后使用 `get_status` 找到未完成任务继续。替代或取消未发布运行沿用 Q53 的资格撤销规则；补件默认进入下一轮。

项目工作区以 `projects/<project_id>/` 隔离，结构化状态为唯一权威。每轮固定材料、场景与有效配置、基础修订；迟到或重复提交按任务身份与输入版本校验。只有整份候选通过发布门槛才成为当前版；材料缺口可形成完整待复核版，错算、丢章、坏引用或必需文件导出失败不能降级绕过。

## 4. 配置与接入边界

沿用[ADR-0008](adr/0008-engine-layout-and-scenario-config.md)及[ADR-0011](adr/0011-per-run-source-and-report-plan.md)：每个场景包使用 `scenario.yaml`、`outline.yaml`、`analysis.yaml`、`quality.yaml`，只引用经过测试的注册算子及包内资源。项目覆盖按 Q54 的类型化白名单合成并冻结；未配置业务定义按 Q55 披露影响，不由模型猜公式或阈值。分享记录中的单个 `config.yaml` 和场景 `formulas.py` 是早期方案，与较新的四文件契约冲突，不混合实施。

第一版本只有 Python CLI 作为宿主调用报告引擎的北向入口，不交付北向 HTTP 接口或 MCP 服务。日后若增加这两种入口，薄适配器调用同一个应用服务及同一项目状态，不复制状态机、计算和发布规则。Q59确认授信专业信息的南向HTTP/MCP接入契约保留在共用检索模块，首期用合成服务验证任务、归档、核验和失败路径；真实供应商联调另行验收。已取得的专业记录可作为标明来源的上传材料，但不能据此宣称完成实时接入。当前三个场景默认关闭检索；授信项目可显式启用合成南向 HTTP/MCP JSON 检索，真实服务的 SSE、认证和供应商字段仍待联调。

## 5. 验收顺序与尚待输入

| 检查点 | 可审查证据 |
|---|---|
| 预算首次完整交付 | 原件处理清单、本轮需求与章节 DAG、关键数值手工预期、全部单位的利润表/经营指标或缺口表/可比图、可打开的 MD/DOCX、质量与版本清单 |
| 预算多轮 | 补件、更正、改章与失败恢复；受影响章节重算，无关正文及资产复用，旧版不丢失 |
| 授信差异验证 | 同一引擎加载授信包；外部结果缺失/后补、专业检索线索与可用证据分离、风险事项去重及策略依据 |
| 南向契约验证 | 通用HTTP/MCP提供者契约使用合成服务；结果归档、主体/时点核验、失败与缺口可追溯；真实供应商联调单列未完成 |
| 薪酬差异验证 | 同一引擎加载薪酬包；核对群体统计、跨期奖金与转岗口径、缺人效分母、小样本及交叉表展示限制 |
| 三宿主验证 | 对每个场景以相同材料、场景版本和操作分别执行 CLI；记录宿主/模型版本、文件可达性、事实及质量结果 |

真实企业材料与模板、授信政策、外部服务接口、薪酬口径与小样本参数、允许模型接触的材料范围和各场景正式版门槛需要用实际样例补齐；缺少这些输入时只报告合成样例的验证结果。真实供应商联调另行验收，用户 Word 自动导入为模板不属于第一版本已确认范围。
