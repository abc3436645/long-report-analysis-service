# 通用外部检索模块与证据契约

版本：设计契约v0.5及实施对照｜日期：2026-10-23｜依据：既有确认、v2.0审查及Q59；合成 HTTP/MCP JSON 服务已验证任务、原始响应归档、状态区分与时效复用。真实供应商、SSE、认证和完整三宿主联调另验。

关联：[主框架](通用长报告项目-统一架构与业务流程.md)、[模块契约](模块设计-数据与执行契约.md)、[决策记录](架构细化-决策树与访谈记录.md)、[授信场景](scenarios/财务公司授信评审-场景规格.md)。

## 1. 模块定位

外部检索是通用报告引擎的共享能力，预算经营、授信风险审查和其他场景均可使用。场景配置决定是否启用、需要哪些检索及如何用于分析，模块中不写“财务公司专用检索”“预算专用搜索”的业务分支。

共享的是执行、接入、来源归档和检索状态；业务问题、检索任务及质量要求属于场景配置。服务地址、工具名称、认证引用和实际能力属于提供者/部署配置，不复制到每个场景。

检索模块返回检索素材及其状态，不生成授信额度、授信等级、风险策略或报告结论。策略与结论由分析、写作和审阅模块基于有效证据形成。

## 2. 与现有模块的分工

| 模块 | 职责 | 明确边界 |
|---|---|---|
| scenario | 声明启用状态、任务需求、适用条件及业务质量要求 | 不实现HTTP/MCP协议，也不保存供应商密钥 |
| planning | 根据配置、项目对象及本轮变更生成标准检索任务 | 不复制提供者调用逻辑；不依靠模型决定程序路由/重试 |
| retrieval | 按任务执行、记录覆盖/失败/时效、归档结果，按规则处理复用和刷新 | 不判断是否授信、不写正文，不将调用成功当作事实已核实 |
| adapters | 实现HTTP与MCP等提供者接入，并承担宿主CLI/MCP入口的协议转换 | 北向报告工具接口与南向来源调用分开；不内置场景分析逻辑 |
| ingest | 对检索返回的文档、页面或结构化记录解析与定位 | 不把解析成功直接当作业务结论成立 |
| evidence | 核对主体、时间、口径与来源，接收候选事实并管理冲突/缺口 | 不因数据来自专业软件就免除核验 |
| analysis / composition | 形成指标、分析发现、风险策略及章节 | 引用证据，不以模型记忆补充未取得事实 |
| validation / project / storage | 校验来源与覆盖，保存任务/证据/报告版本，统一提交 | 不另建一套检索专用项目生命周期 |

模块是单体内的职责划分，不要求独立部署搜索服务或建立新的任务平台。

## 3. 接入方向与业务流程

```mermaid
flowchart LR
    S[场景配置与项目要求] --> P[planning：标准检索任务]
    P --> R[retrieval：通用检索执行]
    R --> H[HTTP服务适配]
    R --> M[MCP服务适配]
    H --> A[结果归档及执行状态]
    M --> A
    A --> I[ingest：解析及定位]
    I --> E[evidence：来源与事实核对]
    E --> F[分析、写作、审阅与完整报告]
```

HTTP或MCP按提供者实际服务能力配置，不按场景名称选择。工程上建议默认由报告工具端适配器执行并登记结果，宿主按已规划任务触发和继续分析；具体SDK/传输版本在三宿主联调前核验，不同时建立另一套相互覆盖的检索状态。

宿主通过MCP调用报告工具，是北向接入；报告流程通过MCP访问专业来源，是南向接入。二者角色、配置与错误来源不同，不能把“安装报告MCP服务”当成已经连接企业查询或搜索服务。

检索阶段在本轮依据封存前归档已取得结果及未取得部分的状态和缺口，不要求所有检索成功才进入后续分析。新结果先成为来源素材，再经核对进入证据快照；冻结之后出现的刷新结果按既有运行/版本规则处理，不能悄悄改变正在写作的依据。

归档内容完整落盘后，才提交结果与运行关联；证据快照登记实际来源版本和缺口，不直接引用提供者可变的最新链接内容。结果未登记、来源未核对或快照未封存时，不向正文提供已确认事实。上传解析及主体核对可先执行，具体封存阶段见[模块契约第6.3节](模块设计-数据与执行契约.md)。

## 4. 三类配置建议

### 4.1 场景配置

用户已确认由场景控制是否使用检索。以下只演示共用结构，不表示预算场景的缺省启用值已确定，也不是现成可运行配置。

```yaml
# 预算经营场景：演示启用行业背景任务；也可明确配置enabled: false
retrieval:
  enabled: true
  tasks: [industry_context]
```

```yaml
# 授信风险审查场景：同一模块，任务不同
retrieval:
  enabled: true
  tasks: [enterprise_background, external_events]
```

任务定义建议包含主体选择、信息需求、提供者能力、检索范围及结果用途；场景声明必要证据和覆盖要求。Q42已修正缺口处理为继续报告并说明或请求补件，Q43确认按场景时效复用/刷新，具体检索清单及有效期仍由场景配置，不预设统一默认值。

### 4.2 提供者配置

提供者配置建议记录逻辑ID、能力、HTTP或MCP接入方式、服务/工具引用、认证引用、请求与结果映射、超时及重试规则。实际服务地址和权限由部署提供，不从“企查查”“Google类搜索”等例子推导出官方API、工具名称或可用账户。

同一提供者可被多个场景使用；替换提供者时保持通用结果契约，对变更后的来源、覆盖与质量重新验证。检索模块不按模型临时判断任意切换到未经配置的服务。

### 4.3 项目与本轮任务

项目明确被查主体、允许发送的查询信息及业务时间范围。本轮任务绑定输入版本，保存实际查询条件和结果位置。已确认的场景规则生成明确任务后正常执行，来源/主体或权限范围不明时才按既定例外流程处理，不每步增加人工确认。

## 5. 统一结果建议

以下为本项目拟议结果字段，不是HTTP或MCP协议天然提供的业务数据；提供者未返回的元数据需标为未知，不能补造。

| 信息组 | 应能表达的信息 |
|---|---|
| 任务关联 | 项目/运行/任务、请求版本、提供者、能力、实际调用方式 |
| 主体 | 被查主体及标识、查询名称、返回主体和匹配情况；别名/重名歧义单独处理 |
| 查询 | 实际条件、范围、分页或其他覆盖限制；敏感信息按项目可见范围处理 |
| 时间 | 实际检索时间、来源发布/更新或数据截至时间（可获得时），未知值明确标记 |
| 状态 | 调用失败、查询未命中、部分结果、结果可取得等，不混成一个成功布尔值 |
| 内容 | 实际取得的文本/结构化返回/资源引用、可归档内容、来源URL/记录位置及内容哈希 |
| 类型 | 企业信息记录、搜索命中/摘要、原页面或原文档等，以便后续采用适当核验要求 |
| 限制 | 权限、未取到原文、覆盖不全、查询截断、时点不明及其他影响解释的事项 |

归档的是接口实际返回的结果，不声称取得了提供者未暴露的内部原始数据。返回资源链接时，还要区分已取得链接与已获取其内容。

### 5.1 调用状态与证据状态分开

调用成功只说明一次技术执行结束；没有命中只说明在已执行范围内未取得匹配结果；关键事实是否可用于报告，由来源、主体、时间及内容核对决定。空结果、查询失败和资料未提供不能写成“没有风险”。

Q44已确认：搜索命中/摘要先作为线索；关键事实应取得并核对可追溯原文或专业记录的主体、时点和上下文。无法核实时保留来源身份、待核实及影响说明并继续报告，不能将摘要重写成确定事实。专业软件结论也核对适用范围，不以调用成功或来源名称代替核验。

核验通过仍只支持其实际涵盖的论断，不自动证明因果、风险不存在或授信等级成立。任务结果保留线索与核验依据的关联；关键事实采用是否合适由语义审阅核对，引用可定位等硬检查由程序完成。具体记录字段为工程建议，不要求所有来源提供同一种原文。

### 5.2 MCP资料核验

本轮通过Context7查阅官方MCP 2026-07-28工具与schema文档：工具结果可通过文本/结构化内容和资源链接表达，工具执行错误与协议错误分开。因此本项目应在适配层保留实际错误及结果形态，再映射到自身业务状态；协议成功本身不定义主体是否匹配或结论是否成立。[MCP Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)、[MCP Schema](https://modelcontextprotocol.io/specification/2026-07-28/schema)。

这是资料核验，不代表目标供应商或三宿主已经实现该版本。具体协议兼容和服务结果仍须实测；本轮未调用任何企业查询/搜索业务接口。

### 5.3 已确认：检索缺口不阻塞进程（Q42）

必查证据不足可能来自调用失败、查询方式不适合、覆盖不足或材料缺失，不能直接推断业务单位存在问题或没有风险。记录实际查询方式、范围、返回状态及影响；原因未能确定时说明未知，不将猜测写成已定位故障。

报告继续执行能够完成的分析、写作、审阅和完整交付，不等待全部检索成功或用户补齐资料。相关正文与问题清单说明缺什么、为何未能取得（已知时）、影响哪些判断，以及可补充的材料/查询信息；需要用户补件时提出具体要求，收到后按补件流程更新。

程序可按已配置、获授权且有上限的规则重试或采用既有替代方式，不能无限等待、让模型自行切换服务或把失败任务标成成功。一次取证尝试结束后，即使有缺口也能进入后续阶段；证据充分性保持独立记录，不靠“任务已结束”自动满足必要证据。

本条确认的是进程继续，不取消Q11/Q22已确认的交付身份规则：必要证据仍不足时完整交付待复核版；如上传补件或其他经核验来源已满足该证据要求，原接口失败本身不再阻断正式版。错算、坏引用、丢章和导出失败仍须修复。

### 5.4 已确认：项目内复用与按需刷新（Q43）

按场景时效规则复用项目内已归档结果。主体、查询条件/时间范围变化、有效期届满或用户要求刷新时，重查相关任务；新增材料通过这些条件及依赖关系决定影响范围，不每轮重查全部，单纯措辞修改不自动触发检索。

保留实际检索时间及可获得的来源数据时点；未知明确标记。有效期由场景声明，不编造统一天数，也不默认跨项目共享敏感结果。封存后取得的新结果进入后续更新；有效依据变化即使正文不变，也按Q27重新判断版本变化。

### 5.5 调用、证据与交付资格的判定矩阵

以下按Q11/Q22/Q42/Q44展开已有规则，不把一个成功布尔值扩展为全部质量结论。表中“可正式”均以其余场景门槛、独立审阅和呈现检查满足为前提。

| 技术执行结果 | 证据核验及覆盖 | 对完整交付与身份的影响 |
|---|---|---|
| 调用失败/覆盖不足 | 上传或其他已归档来源经场景采用规则确认可替代，且覆盖同一必要要求 | 调用保持失败/不足，证据可充分，报告可正式；不得伪造成功，也不能把局部事件记录当作覆盖全部范围 |
| 调用成功 | 主体不符、时点不明、仅有不能支持关键事实的摘要 | 不算必要证据已满足；继续交付并说明，相关必要要求不足则待复核 |
| 未命中 | 查询主体、范围和执行覆盖明确 | 只说明已执行范围内未取得匹配记录；是否满足该取证要求由场景声明，不直接证明无风险 |
| 调用失败/部分结果 | 无适用替代证据，必要要求仍不足 | 按Q42继续分析和完整待复核交付，说明限制及具体补件要求 |
| 调用成功且内容已归档核验 | 所需主体/时点/内容及覆盖满足 | 可用于其实际支持的判断，报告可正式；不将来源结论自动当作因果或授信结果 |

来源要求、任务执行状态、证据采用状态与报告身份分别保留。固定字段与实际提供者返回映射仍待schema/样例验证；矩阵不声称实际服务已经通过测试。

## 6. 外部授信结果与通用检索的区别

授信模型输出额度，专门流程输出授信等级，期限依等级确定。这些是具有独立业务来源的评估结果；报告可以接收并核对，不在通用检索模块运行或重建其产生模型。

即使业务结果将来通过同类HTTP/MCP适配取得，也要保留其“授信模型/等级流程/期限规则”身份。专业软件给出的评分、搜索摘要中的评级，不能自动代替用户指定的授信等级。

Q46确认风险报告可先行，缺少结果时披露缺口，不等待额度/等级流程全部完成；既有结果提供后按补件核对主体、版本、时点及期限关系，并更新相关审查与策略。首期不自动发起或重跑这些业务流程。传递介质、字段和结果是否为正式版必需输入仍由实际接入及场景规则确定。

## 7. 待决与验收

Q42按用户修正确认继续进程，Q43—Q47确认复用、来源采用和授信业务边界；授信章节已由Q48确认。Q37已接受，Q38/C05明确三个配置场景共用本模块，Q52确认关联更新与无关正文哈希保护；具体检索清单、提供者和字段仍需样例与实际接入验证。

Q59确认首期用合成HTTP/MCP服务验证通用提供者契约与失败路径；真实供应商的端点、凭据、字段及联调单独验收。已取得的专业记录可以按有来源的材料输入，但不因此把上传路径称为实时服务接入。当前三个场景默认`retrieval.enabled: false`；授信项目可白名单启用合成服务任务。现有南向 MCP 适配器仅解析 JSON 工具响应，不宣称支持 SSE 或已通过真实服务协议兼容验收。

实施时至少验证：两个不同场景调用同一检索模块；关闭场景不创建任务；更换HTTP/MCP提供者不改变业务流程；失败/未命中/部分结果不混淆；必查取证不足仍生成有缺口说明的完整待复核报告并给出补件要求；补件满足证据后重新评定身份；有效结果复用、过期/相关条件变化/主动刷新只重查受影响任务；措辞改稿不重查；新依据按依赖影响版本。具体有效期使用样例场景参数；不能声称尚未执行的验收已通过。

Q44/Q46增加的验收意图：仅有摘要且无法核实时不能出现对应的确定事实；取得专业记录后可追溯核验依据；主体/时点不符的记录不得直接采用；外部额度/等级缺失不阻塞风险报告、后补结果触发相关更新且不启动外部模型。这些仍为待实施验收场景。
