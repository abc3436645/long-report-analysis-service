# 预算经营分析：场景规格

版本：业务规格v0.6｜日期：2026-10-23｜状态：Q7—Q30及适用根决策、C04和Q42—Q43已确认；具体字段、场景参数与真实样例继续验证。

依据：[统一架构](../通用长报告项目-统一架构与业务流程.md)、[决策与访谈](../架构细化-决策树与访谈记录.md)、[业务术语表](../../GLOSSARY.md)。本文件记录业务要求；可执行场景配置见 `scenarios/budget_operations/`，实跑状态见[首期工程验收记录](../../.scratch/long-report-first-release/acceptance-2026-10-23.md)。

## 1. 使用者、读者与业务目标

财务或经营分析人员使用工具编制，主要读者为企业管理层和经营会议。报告需要帮助读者理解经营表现、预算差距、相关原因和应采取的行动，不默认承担审计鉴证用途。

每个生成/修改轮次交付完整可访问 Markdown、DOCX 与 PDF。对话提供文件、变更说明和待确认事项，普通问答复用当前版本。

实施对照：`scenarios/budget_operations/analysis.yaml` 只保存稳定的计算口径与写作要点，不保存 `reference_2026_07` 来源配置。本轮 MOCK 工作簿的映射只作为每次运行时检查原件后提交的输入；历史映射位于测试夹具，不能作为其他月份或真实企业材料的默认证据。

“全范围覆盖”与“重要单位加深”是两项要求。重要性影响分析深度，不改变必需覆盖范围。Q24已明确身份、组织与排序规则；真实单位层级、别名和加深条件由项目/场景数据提供，不能凭示例猜定。

首期可执行约束：Skill 按用户要求与本轮主表确定 `subject_scope.units`，板块合计和独立专项按独立主体登记；自动提取时不在项目范围的原表行必须说明排除理由，发现应纳入的单位则更正范围。`draft plan` 的 `unit_names` 必须与项目单位同序，并有逐单位章节。预算计划还须用 `material_uses` 对本轮每份材料作 `analysis`、`context` 或 `excluded` 决定并说明原因；有已接受证据的材料必须用于分析。逐户正文若有本轮成本、生产量、铜精矿或硫精矿证据，须在经营表、解释文字中引用该主题的计算结果（不可计算时引用事实）及来源。交付门禁复查分析材料、逐户主体和独立专项是否真正进入正文；这些规则从当轮证据触发，不预置某期单位、来源单元格或固定目录。内容深度、业务解释和建议仍由独立语义审阅及参考稿对照验收。

## 3. 分析所需的信息范围

已确认需要识别：报告对象及单位范围、报告期、实际与预算的身份、年度与进度期间、同比基准，以及支持原因判断的材料。比较数据必须具有可比口径，未提供与零值不能混淆。

核心指标族、预算版本选择原则、集团/单位数据区别及输入格式已经确认。利润总额、净利润等类型必须明确，不能同名混算；现金流、应收、负债等按资料和需求启用。具体字段、公式、抵销规则、专项数据边界和数值精度仍待细化，不将旧方案示例直接当作正式要求。

Q23已确定默认计算边界：差额为实际减基准；正基数使用声明公式，零/负基数默认表达差额和明确状态。特殊百分率、指标有利方向及展示精度由场景声明；先按未舍入值计算，再展示。不能把成本费用完成率越高直接写成表现越好。

预算办参考稿还使用“剩余月份月均利润目标”：在本年累计利润和全年计划同口径、报告月早于十二月时，按（全年计划－本年累计）÷剩余月份数计算，由 CLI 留存来源与公式。结果为负时说明年度计划已经超过，不将负值说成未来盈利要求；缺全年计划或期间口径不一致时不生成该指标。

预算版本需要记录身份、生效期间和作用范围。没有明确指定或适用规则时请求裁决；文件较晚上传不等于全面替代旧预算。集团报表缺失时，未经范围及必要抵销核对的单位汇总不能冒充合并数。

报告的主要分析单元应能分别回答：

1. 本对象在当月及累计期间表现如何？
2. 与有效预算及同口径上年同期相比，差距或变化在哪里？
3. 哪些原因有依据，哪些只是待核实假设？
4. 有哪些需要关注的问题或风险，影响是什么？
5. 建议采取什么行动，有哪些前提或信息限制？

这些是内容要求；默认章节见下一节，不要求用冗长重复文字填满所有单元。

## 4. 首期预算报告章节

| 部分 | 内容职责 |
|---|---|
| 报告口径与资料范围 | 交代期间、材料覆盖、预算版本、合并范围及限制 |
| 各单位经营分析 | 对所有纳入单位逐一覆盖，分别说明表现、原因、问题、建议与缺口 |
| 专项来源的独立口径 | 单列不能直接归入单位或集团结果的专项材料 |
| 整体经营与共同关注事项 | 从已有单位和专项分析形成整体观察，不用单位简单加总冒充合并口径 |
| 市场关联及情景测算 | 明确市场材料适用范围，区分情景假设与已发生事实 |
| 建议事项与人工确认 | 汇总逐户复核、协同方向、需确认口径和补件要求 |
| 来源索引与计算口径 | 集中列明比较口径、预算版本、来源与缺口；关键限制仍需在相关正文披露 |

本节章节顺序是参考报告的一个实例，不是场景默认目录。Q25及本轮预算办 Prompt V2 要求：有利润事实的每个独立单位均有利润比较表和经营指标表或缺口表；至少一组可比数值时有本单位自己的图。用户模板优先，表格可编辑、图表实际嵌入、来源可追溯。零、负基期或转亏不强算变化率；年度计划完成率与序时计划完成率分开。

逐户分析应区分确认事实、业务解释和待核原因，并选出本单位真正影响经营判断的差异。矿山重点把选矿处理量、金属折合量、吨矿与金属成本、变动成本、人工折旧、铜金银及硫精矿的产销量价分开；不能从处理量与金属量推断品位，也不能将产销差当作库存。冶炼、铜加工、贸易及金融单位按自身经营模式选指标。经营计算不能只放在表格里，正文须引用并解释关键变化。每户管理建议说明数值证据、可能影响、责任部门和需要补充的台账；不机械复制同一句降本建议。上述稳定要点写在 `analysis.writing_guidance`，项目和轮次仍自行决定覆盖单位、章节与依赖。

场景与项目可明确调整结构，不依赖“第几章”作为长期定位方式。单位显示顺序依用户指定/模板、组织顺序、稳定缺省顺序选取，与分析深度分开。

依据 [ADR 0010](../adr/0010-budget-four-reference-acceptance.md) 与 [ADR 0011](../adr/0011-per-run-source-and-report-plan.md)，本轮 MOCK 材料的预算办、矿山、冶炼、铜加工四份 DOCX 均作为参考交付，不预置三个板块 profile。Skill 按每次用户需求和当前原件决定单位范围、章节与依赖；主报告的 42 个主单位及 10 个嵌套单位只属于该参考材料。母子单位、板块合计与集团合并行保持独立口径，未经核实不得相加。环比、同比、序时差额及基期可比时的变化率和计划完成率由注册算子计算；图表从冻结证据及注册计算生成并保留引用。

## 5. 业务流程与模块落点

| 阶段 | 要得到的业务结果 | 对应模块 |
|---|---|---|
| 项目建立 | 明确场景、期间、对象范围和模型可见材料范围 | project、scenario |
| 材料登记与提取 | 每个文件有处理结果，事实可回到原文，未提供信息形成缺口 | ingest、evidence |
| 外部检索（按配置） | 启用时取得并归档所需外部素材，关闭时不创建任务；结果核验后才用于分析 | planning、retrieval、adapters、ingest、evidence |
| 口径与来源处理 | 区分期间/预算身份、材料更正与冲突，不能裁决的事项等待用户 | evidence、planning |
| 指标与比较 | 在同口径下执行确定性计算；无法比较时输出原因 | analysis |
| 单位及专题分析 | 覆盖所有单位，分别形成原因判断、问题和建议，标注依据与限制 | planning、composition |
| 摘要与整合 | 摘要和主要结论与本轮有效分析一致 | composition、validation |
| 完整交付 | 所需文件有效，关键缺口披露，保存版本和变更 | validation、rendering、project |

原六部分及七部分目录仅供本轮规划参考；管理层摘要是否列入、专题如何展开，取决于本次用户需求和材料覆盖。原因、风险与建议的专业性按预算办 Prompt V2 审查，不能用来源值复述替代分析。

检索复用[通用检索契约](../外部服务接入与证据契约.md)，可用于场景声明的行业等背景信息，不能替代单位实际/预算材料。Q42确认必查信息不足不阻塞报告进程，说明限制或提出补件要求；必要证据未满足时完整交付待复核版。Q43确认按场景时效复用项目归档结果，主体/查询条件/范围变化、过期或用户要求时重查相关任务，单纯改措辞不重查。预算默认启用值、具体检索清单和有效期仍需配置。

## 6. 典型多轮情境与业务验收

| 情境 | 需要满足的结果 |
|---|---|
| 个别单位无材料 | 单位不消失；对应分析说明缺什么及影响，补件清单可定位该单位 |
| 缺月度预算 | 不用年度预算除以12冒充已确认月度预算，不将不可比较写成偏差为零 |
| 补充经营说明 | 更新其支持或否定的原因判断，以及依赖该判断的摘要/建议 |
| 更正利润数据 | 更新相关指标、表图及依赖结论；集团总量是否受影响须按后续明确的集团口径判断 |
| 只改第三章语气 | 目标正文更新，其余正文保持；事实和关键判断不被暗改 |
| 事实变化但摘要被锁定 | 保留锁定内容，显式提出冲突并请求解锁决定；不得悄悄覆盖 |
| 新月份建立项目 | 复用结构和固定配置版本，重新确认本期数据身份，上期值仅按明确用途使用 |
| 本轮构建失败 | 不将旧版标成本轮新交付，不以待复核名义掩盖文件或内容硬错误 |
| 同文字但更正来源 | 有效依据变化形成新修订，不能因文字相同跳过版本记录 |
| 并行任务使用旧依据 | 拒收过期结果，不覆盖当前任务和报告状态 |
| 必需审阅没有执行 | 不能标正式版；明确报告检查状态，不把未执行算作通过 |
| 回退到旧稿 | 形成新修订、重新验收所选依据，历史保留；不声称旧内容已覆盖后续新材料 |

## 7. 下一步模块契约与验收

前4轮Q1—Q30已确认，已写入[模块数据与执行契约](../模块设计-数据与执行契约.md)。字段名、配置语法和实际实现仍是工程表达，需要验证，不能把文档视作已运行功能。
