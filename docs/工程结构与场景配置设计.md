## 1. 取舍与目录原则

三个需求分析分别提供通用引擎与证据职责、Python 引擎加 Skill/MCP 壳、CLI＋MCP＋Skill 分层交付。最终规则以[统一架构](通用长报告项目-统一架构与业务流程.md)及已确认决策为准。目录图表示责任归属，不要求预先创建空模块。

| 早期示例 | 最终设计 | 依据 |
|---|---|---|
| 根 engine/ 平铺解析、状态、组装、CLI、MCP | 一个 src/long_report Python 包；业务模块按增长拆分，接入归 adapters/ | 一个应用服务和一个发行包 |
| core/、parsers/、operators/、renderers/ 各自先建目录 | 对应逻辑职责保留；小模块先用单文件，实际需要时拆目录 | 主架构第 11 节 |
| 顶层 scenarios/ | 保留，三个并列场景各有四份核心 YAML 与实际引用资源 | 主架构第 6 节、C05 |
| 场景 formulas.py 或配置中的可执行公式字符串 | 已注册、经过测试的通用算子；配置只引用算子 ID 和类型化参数 | ADR-0005、Q20 |
| 每宿主单独维护 Skill SOP | .agents/skills/long-report/SKILL.md 为唯一源；平台壳复制并核对内容 | 主架构第 10.1、11.1 节 |
| 单一全局 .report_workspace/，多个可写 JSON | projects/<project_id>/ 独立工作区；结构化状态为唯一权威，清单由其导出 | 主架构第 11.2 节、ADR-0003 |
| 终端打印或聊天拼接全文 | 返回完整可访问 MD/DOCX 文件及状态，PDF 按场景启用 | ADR-0002、Q2 |

## 3. 场景配置包 v1

四个 YAML 组成一个固定版本的有效定义。`outline.fixed`缺省为false；为true时`sections`须完整且每章显式提供`subheadings`，`quality.required_sections`覆盖全部固定章节。章节可声明`required_tables`，以二级标题及可选`child_heading`定位必需表格；两列字段清单用`required_fields`，逐户明细与合计用`total_row`，两者择一。`required_subsections`以title/content固定指定二级标题下的三级标题及table/narrative呈现；字体字号集中在scenario的`presentation.styles`和`presentation.table_styles`，章节表格只用`style`引用命名样式，未引用时继承默认表格样式；固定计划不能移除或覆盖该规则，渲染与读回验证只作用于对应表格。`presentation.cover`按需声明标题模板、额度选择器、显示单位、字段来源／默认值及运行日期时区；尽调专有内容通过配置启用，渲染器共用。`presentation.allow_font_fallback`缺省为true；为false时缺少任一指定字体便拒绝渲染。字段名为本次选定的工程契约；尚未填定的企业业务参数使用显式 null 和定义缺口，不编造默认值。三个场景共用加载器、校验器、计划器和接口，不在公共流程写场景 ID 分支。

| 文件 | 最小字段与责任 | 不放入的内容 |
|---|---|---|
| scenario.yaml | schema_version、id、version；对象与时间模型；材料种类与必需性；检索开关和任务引用；资源路径；presentation文档/表格样式、金额展示及按需封面绑定；required/optional 交付格式；可覆盖字段路径、类型与范围 | 供应商地址/密钥、章节正文、可执行公式 |
| outline.yaml | 稳定分析要点；动态场景`sections`为空，固定场景声明`fixed`及各章`subheadings`、引用和DAG | 单位名单、运行时来源映射；未确认的固定目录 |
| analysis.yaml | evidence_selectors、metrics 的算子 ID/输入/参数、analysis_tasks、retrieval_tasks 与任务依赖 | 任意 Python 导入、eval 表达式、宿主专用工具调用 |
| quality.yaml | 必需材料/对象/章节/表图覆盖；数值、引用、语义审阅、渲染检查；可见字段与小样本限制；正式版条件 | 关闭基础硬检查的覆盖开关 |

三个场景以相同字段组表达差异，以下是配置落点示例，不替代各自业务规格或填写尚未确认的企业参数：

| 场景包 | scenario.yaml | outline.yaml | analysis.yaml | quality.yaml |
|---|---|---|---|---|
| budget_operations | 组织范围、月报当月/累计、实际/预算/同比材料；检索由配置决定 | 月度、预算、单位分析与表图的稳定提示；具体目录由本轮请求生成 | 同口径差额、正基期比率、年度/序时计划完成率；原件映射每轮提交 | 全单位覆盖、关键数值/表图及缺口检查；无月度预算不推算 |
| financial_due_diligence | 授信事项、业务单位、评价基准；专业来源为可配置检索任务，不填供应商密钥 | 固定九章及二级标题、DAG；本轮判断适用专题 | 来源核验、风险事项与策略；外部额度/等级/期限作为待核对的输入，不内建测算 | 关键事实原文/专业记录可追溯，缺外部结果披露限制，风险程度与授信等级分开 |
| compensation_analysis | 人员/群体范围、薪酬分析与比较期间；组成、展示阈值等未确认参数显式留空 | 群体与小样本分析提示；本轮计划章节 | 分组统计及已声明的人效公式；缺分母或公式时停止该项计算 | 个人字段不默认展示，小样本按配置隐藏/合并并检查交叉表反推 |

引用规则：scenario.yaml 指向其余三文件，包内资源路径必须规范化后仍位于场景包内；场景中的算子和分析引用必须存在。每轮提交的报告计划校验章节 ID、证据/分析引用、重复范围与 DAG；`fixed: true`还校验一、二级标题及顺序不能覆盖。`depends_on` 表示本章读取的前置章节；展示顺序与执行顺序分开，摘要可排首位但在基础分析后生成。重复章节按本轮单位身份展开，不能凭章号或通配符隐式形成循环。参见 [ADR 0011](adr/0011-per-run-source-and-report-plan.md)及[固定尽调结构ADR 0014](adr/0014-financial-due-diligence-fixed-report-contract.md)。

算子仅可从共用注册表引用。新场景在已有解析格式、算子与配置能力内只需新增配置包；新文件格式、全新算法分别扩展通用解析器、算子并配对应样例。未知算子在加载时拒绝。场景资源及定义固定到项目版本；升级是显式更新，不静默改变已封存运行或历史修订。

### 3.1 四文件最小示例

可选`presentation.amount_display`声明`table_unit`、`chart_unit`、`text_unit`、`text_large_unit`、`text_large_threshold`（以元计）及`decimal_places`。金额单位支持元、万元、亿元；正文在未舍入绝对金额达到阈值时使用大额单位，表格与图形使用各自固定单位。引用小数位作用于换算后数值，源证据及计算记录保持原精度；未声明时沿用原展示行为。封面额度声明该规则时也按正文分级，否则沿用`cover.amount_unit`。尽调0.3.1的配置与决定见[ADR 0018](adr/0018-financial-amount-display.md)。

以下 contract_example 是旧版固定章节 schema 的历史草案，已由 [ADR 0011](adr/0011-per-run-source-and-report-plan.md) 更新；不能作为当前可运行配置复制。示例用两个 CSV 来源和通用 difference 算子；具体业务比较需先核对主体、期间、单位和口径。

scenario.yaml：

~~~yaml
schema_version: 1
id: contract_example
version: "0.1.0"
subject_model: organization
time_model: period
inputs:
  - {id: actuals, required: true, kinds: [csv]}
  - {id: baseline, required: true, kinds: [csv]}
retrieval: {enabled: false, task_refs: []}
outline: outline.yaml
analysis: analysis.yaml
quality: quality.yaml
delivery:
  required_formats: [md, docx]
  optional_formats: [pdf]
overridable_fields:
  - {path: outline.sections.detail.title, type: string}
~~~

outline.yaml：

~~~yaml
sections:
  - id: detail
    title: 数据分析
    display_order: 2
    repeat_for: null
    goal: 解释同口径差额
    questions: [实际与基准的差额是什么]
    evidence_refs: [actual_amount, baseline_amount]
    analysis_refs: [amount_difference]
    required_assets: []
    depends_on: []
    prompt: null
  - id: summary
    title: 摘要
    display_order: 1
    repeat_for: null
    goal: 汇总已完成分析
    questions: [最重要的发现和限制是什么]
    evidence_refs: []
    analysis_refs: [amount_difference]
    required_assets: []
    depends_on: [detail]
    prompt: null
~~~

analysis.yaml：

~~~yaml
evidence_selectors:
  - {id: actual_amount, input: actuals, field: amount, dimensions: [subject, period, unit]}
  - {id: baseline_amount, input: baseline, field: amount, dimensions: [subject, period, unit]}
metrics:
  - id: amount_difference
    operator: difference
    inputs: [actual_amount, baseline_amount]
    parameters: {}
analysis_tasks: []
retrieval_tasks: []
~~~

quality.yaml：

~~~yaml
required_inputs: [actuals, baseline]
required_sections: [detail, summary]
checks:
  - evidence_location
  - numeric_binding
  - section_coverage
  - independent_review
  - md_docx_openable
formal_requires: all_required_checks_pass
visible_fields: [aggregate_amount]
~~~

章节按稳定 ID 而非数组下标进行项目覆盖，因此示例路径中的 detail 是章节 ID。此最小示例不引用额外资源；若实际场景引用提示词或模板，资源不存在时加载失败。上述 YAML 用于定义目标 schema，不是可直接运行的产品配置。

### 3.2 校验与缺口

| 输入情况 | 结果 |
|---|---|
| 四文件结构合法、ID/资源/算子都存在 | 固定场景版本，生成单一有效配置及指纹 |
| outline 的 summary 依赖 detail，同时 detail 依赖 summary | 拒绝；报循环路径 |
| metric 引用不存在的算子，或证据选择器指向不存在的 input | 拒绝；报文件、字段路径和目标 ID |
| prompt 指向包外路径或文件不存在 | 拒绝；不读取包外内容 |
| 项目覆盖未声明字段、类型错误、越界，或试图关闭数值/引用/必需文件检查 | 整份覆盖拒绝；不部分写入 |
| 业务公式或展示参数允许为 null 但未配置 | 记录 definition_missing 与受影响项；不执行对应计算/展示，其余可完成部分继续并披露 |
| 定义已存在但材料未取得 | 记录 source_missing；不当零或无风险 |
| 输入值为数值零 | 按算子零基数规则处理，不归类为缺材料 |
| 场景明确声明该规则不适用 | 记录适用性依据，不伪装成缺定义 |

项目覆盖至少保存原值、覆盖值、类型检查结果、指令来源、场景/项目要求版本和指纹。规划、任务上下文、分析、验证读取同一已冻结有效配置。展示、顺序、比较版本等已确认可调整要求应由场景声明覆盖路径；项目身份和不可关闭硬检查不纳入覆盖白名单。

## 4. 运行项目与宿主边界

~~~text
projects/<project_id>/
  state.sqlite                    权威结构化状态和版本索引
  sources/                        原件版本或受控外部引用
  parsed/                         解析结果与原文位置
  objects/                        不可变章节、表格、图表等资产
  runs/<run_id>/                  固定输入、候选、错误和恢复记录
  revisions/<revision_id>/        完整报告、变更、问题、验收与版本清单
~~~

项目身份由场景、对象范围及报告期或评价基准确定；不同项目不默认共享事实。manifest、事实视图和变更摘要可从权威状态导出，不另设多个可写真相。原件和已发布资产不覆盖。用户通过对话改稿形成新修订；导出的 Word 被人工改动后需重新作为参考材料引入。

application.py 是唯一领域操作入口。第一版本由CLI接收明确场景ID/版本并调用scenario.py加载和校验四文件；宿主读取稳定分析要求与计算口径，并按本轮需求和原件提交章节及依赖计划，由核心校验和执行。CLI只做输入、结果及错误映射，读取同一项目工作区和当前版本；后续北向MCP沿用同一职责。Skill制定长报告分析与交付流程，指导状态检查、待办、提交、恢复及完整文件交付。北向宿主MCP与南向专业来源HTTP/MCP是不同接入方向；Q59确认首期以合成服务验证通用南向接入契约，真实供应商联调另验。`retrieval.enabled: false`是场景默认值，授信项目可白名单启用合成检索；检索启用取决于配置，不在适配器按场景名分支。平台配置不提交密钥或开发机绝对路径；安装时核对宿主环境实际可执行入口和交付文件可达性。三宿主CLI实测属于M4，不能仅凭本设计宣称适配成功。
