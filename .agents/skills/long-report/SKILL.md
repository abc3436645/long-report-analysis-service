# 长报告主控流程

1. 识别用户本轮要求、场景、报告期或评价基准、对象范围和交付形式。预算报告先将用户要求与本轮主表核对，形成应覆盖单位清单：例如用户要矿山板块，就只把该板块内可确认的独立单位纳入 `subject_scope.units`，板块合计与独立专项放入 `special_subjects`，并保留主表顺序；缺数据的在范围内单位仍保留。可从文件初步识别单位与字段；不能把文件名或历史项目证据当作本轮事实。场景含 `budget_operations`、`financial_due_diligence`、`compensation_analysis`。用户在对话中增加分析要点时，更新本轮要求；已发布报告通过新运行修订。
2. 财务尽调场景先读取[财务证据与计算操作](references/financial-quality.md)，在材料归档、计算和审阅三个边界逐项完成核验。运行 `report scenarios`、`report scenario <id> --version <version>`，读取场景稳定的材料类型、指标算子、`analysis.writing_guidance`、质量规则和 Word 模板。场景包不预置单位名单和来源单元格映射。尽调的presentation.cover绑定本次公司、额度及运行日期；项目可用report_metadata.prepared_by/account_manager指定呈报部门和经理，未指定按配置填XXXX，不自行替换为样本人员。`financial_due_diligence`的`outline.fixed`固定一、二级标题；预算与薪酬按本轮需求规划章节。逐份先直接读取用户本轮提供的文件，按[财务证据与计算操作](references/financial-quality.md)第4节由Agent判断是否确需OCR补充，不按文件类型批量调用；记录进入数值分析、仅作背景和排除的依据；再调用 `report project create` 和 `report material add` 归档原件；`--request` 指向 UTF-8 JSON 文件，`--workspace` 指向项目目录。
3. `report run start` 固定本轮材料；逐项查看 `report task list/context` 返回的解析结果，在当前文件中识别主体、期间、字段和定位。对结构稳定的当前工作簿，可将**本轮检查过的**行列映射作为 `mapping` 传给 `report task auto-submit`；其他来源用 `report task submit`。自动提取若发现原表主体不在项目范围，须核对 `excluded_rows`；确属用户要求之外时提交 `scope_exclusion_reason`，发现少列的矿山则更正项目范围后重跑，不能把遗漏写成排除理由。候选须经来源、口径、公式及冲突核对，再由 `report evidence decide` 接受，最后 `report evidence freeze`。不得把上传顺序当作冲突裁决。专业检索任务按场景要求执行并核对原始响应，失败与空结果进入缺口。
4. `report calculate` 从本轮冻结事实计算注册指标。区分金额差额、变化率、序时预算完成率、年度计划完成率和剩余月份月均目标；目标已超额时不要把负的剩余额说成未来盈利要求。基期为零或负、转亏及不可比时使用状态说明，不能编造百分比。预算、授信和薪酬所缺的业务定义须披露，不能凭模型猜测。只引用本轮返回的 `{{fact:<id>}}`、`{{calc:<id>}}` 与 `{{ev:<id>}}`。
5. 根据**本轮用户需求和已确认材料**制定完整章节、单位顺序、每章分析目标、证据与计算引用、必备表图以及 `depends_on` DAG。尽调场景将已加载的`outline.sections`提交为本轮计划，保留固定章名、二级`subheadings`及顺序、已声明的`required_subsections`三级标题与`required_tables`表格契约，正文按`##`提交小节，标题与正文之间及各块之间保留空行；引用展开后如出现原件中的标题冲突，应改用对应事实片段或明确引述，保持固定结构；资料不足也保留标题并披露，第四章不新增二级标题。字体字号按场景presentation中的文档样式和命名表格样式统一定义，章节只保留样式引用；缺仿宋须明确报错，不能静默替换。预算场景首次调用 `report draft plan` 时同时提交 `report_request`、`outline` 和逐份 `material_uses`（`material_id`、`use: analysis|context|excluded`、`reason`）。`outline.unit_names` 必须与项目单位清单同序且有逐单位章节；有已接受证据的材料须标为 `analysis`。逐个核对本轮单位、板块合计、独立专项和材料的去向，缺资料列明缺口，不能通过缩小章节计划隐藏它。`analysis_refs` 可引用本轮 `report calculate` 返回的指标 ID，例如矿山成本的逐行同比差额；没有实际计算出的指标不能凭空列入。预算办月报、矿山报告和其他板块报告可有不同章节和单位范围。摘要可排在前面但依赖主体分析后写；不得把参考报告目录复制为所有项目的固定计划。新增要点需要改变已生成的章节任务时，取消未发布运行后重开，或在已发布版本上开新运行并提交新计划；旧版本不改写。
6. 财务尽调按场景`body_and_annotations`与`chapter_body_focus`区分业务正文和原生Word批注，逐章expression审阅确认主题充分及实质风险保留；核查与编稿说明不进入正文。按 `report draft context` 返回的本轮事实、计算、材料用途和场景写作指引逐章写作。预算单位的经营综述按月度变化、累计同比、序时预算、全年计划的顺序展开；按本单位业务类型选择 `mining_focus`、`smelting_focus`、`processing_focus` 或 `trade_finance_focus`，不能把矿山指标套到非生产单位。有数据时逐户写利润比较、单位图、生产成本与产销变化、经营判断、管理关注和人工确认；逐户核对本轮证据中出现的成本、铜精矿和硫精矿等主题，能计算时使用本轮计算指标，不能计算时引用原始事实并披露缺口。利润表、经营指标表须使用本单位数据、编号和来源定位；图用 `report chart create` 制作，在利润表与指标表之间使用 `{{chart:<id>}}`，并解释图示变化。经营计算除列于指标表外，还须在解释文字中引用、比较并说明管理含义。原因说明区分已证事实、业务逻辑和待核假设；管理建议写证据、可能影响、动作、责任岗位及前提。不要把指标表搬成段落、把专项量价差直接当作利润归因，或用相同空泛措辞替代逐户分析。集团、板块、母子单位、专项各自保持口径。
7. `report draft build` 后用预算办参考稿与本轮场景指引审查内容深度、数值与来源；逐项核对 `material_uses` 的分析材料、本轮单位与独立专项在正文中的实际落点，由真正独立于作者的审阅者按事实、解释、决策和版式复核，再调用 `report review submit`。运行 `report validate`，尤其检查 `material_disposition`、`analysis_material_coverage`、`unit_scope_coverage`、`unit_evidence_coverage` 与 `special_subject_coverage`；失败逐项修复，再调用 `report publish`。检查最终 MD、DOCX 与可用时的 PDF：逐户确认表图位置、字体、封面、目录实际页码、图片可见和来源；目录只是标题列表或页码不符时不能称为完成。`pending_review` 明确列出未确认口径、业务签认和实际未执行的验收。

当前旧版 MOCK 报告和三宿主脚本化 CLI 回归是历史工程证据，不能当作新动态规划流程、开放式 Agent 写作或业务签认已通过的证明。`results/budget_operations/` 为参考交付样本，不是预生成证据库。CLI 是首期北向入口；真实供应商检索和宿主自主写作需另行验收。

预算报告排版遵从场景规格第8节及ADR 0012。项目创建时按用户授权填写`report_metadata.analysis_subject`、`prepared_by`和`confidentiality`，不要沿用与本轮范围不符的“集团合并”标签或自行指定保密等级。章节采用第一章/1.1/1.1.1并保留单位原编号和顺序，每张表图注明编号、标题、期间、单位、来源及模拟性质；逐户双表和必要图不能因50页限制删减。封面须区分经营期间、数据快照、实际生成日期和可读报告版本，不以材料日期或内部ID替代。最终PDF须逐页检查，不能用抽查代表全篇验收；静态目录按最终排版实测收敛且含跳转，在Word编辑后需重新生成，不宣称为动态目录。未实际运行Word 2019/Microsoft 365/WPS时只列为目标兼容环境。
