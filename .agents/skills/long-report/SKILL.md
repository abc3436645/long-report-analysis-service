# 长报告主控流程

1. 明确本次是首次报告、补件、更正、修改章节还是普通问答；确认场景 ID、报告对象、期间或评价基准。场景 ID 为 `budget_operations`、`credit_review`、`compensation_analysis`。身份不明时先请用户澄清。完成标准：这些项目身份均已明确。
2. 运行 `report scenarios` 和 `report scenario <id> --version <version>`，读取结构化结果中的材料需求、章节、分析任务、计算引用、质量规则和定义缺口。命令失败时展示错误并停止该轮。完成标准：取得已校验且版本匹配的四文件配置。
3. 按场景要求建立材料清单，区分原文、候选事实、确认事实、确定性计算和分析判断。逐项保留来源、主体、期间与口径；缺材料、缺定义、数值零和不适用分别表达。完成标准：每个要求都有证据或明确缺口。
4. 依章节 `depends_on` 顺序分析，摘要在主体分析之后写；展示顺序按 `display_order`。数值交给已注册算子处理，模型负责提取、解释、判断、写作和独立语义审阅。完成标准：每个适用章节都有依据、结论和限制。
5. 发布前核对数值、引用、章节覆盖、敏感信息展示、表图和文件可打开性；改稿时核对影响范围及旧版保留。仅在引擎返回通过验收的完整 MD/DOCX 文件及版本身份时向用户报告交付完成。完成标准：完整文件与验收结果可访问。

当前 CLI 只实现 `scenarios` 和 `scenario` 两个配置查询命令，返回 `capability: scenario_contract_only`。任务、项目状态、计算执行和完整报告发布尚未实现；到第 3 步后应清楚说明实现缺口，不能把人工草稿或场景模板称作已交付报告。具体业务规则以 `scenarios/<id>/` 的已校验配置和 `docs/scenarios/` 场景规格为准。
